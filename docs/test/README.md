# 测试报告存档

本目录存放**历次测试的报告**。与 [test/README.md](../../test/README.md) 分工不同：

| | 本目录 `docs/test/` | [test/README.md](../../test/README.md) |
| --- | --- | --- |
| 性质 | **报告存档**——某次测试做了什么、发现了什么、修没修 | **活文档**——测试套件怎么跑、分几层、效力边界 |
| 时效 | 记录**当时**的事实，不随后续改动更新 | 随代码同步维护 |
| 读者 | 想知道「这个 bug 当初是怎么发现的」 | 想知道「现在怎么跑测试」 |

**报告里的结论可能已被后续提交修正**，每份报告头部都标了状态。要了解当前行为，以代码与 `test/README.md` 为准。

> ⚠️ **行号会漂移。** 报告里的 `文件:行号` 是**写下当时**的位置，后续提交会让它们失准。凡标「修复前」的是**历史陈述**，对不上是正常的；其余引用若对不上，以符号名（函数名、字段名）为准去搜，别按行号读。

## 贯穿四份报告的一条教训

02 与 04 挖出的是**同一类问题**，值得单独点出来：

> **比对器的期望值必须来自另一条计算路径，否则它就只是内核的复读机。**

02 里 `test/lib/compare.mjs` 的 `expectedAge()` 与内核 `algorithm.ts` 的 `currentAge` **是同一个公式**，内核算错、比对器跟着错，300 条基准逐条"全等"。修复后加的那条反向实验最能说明问题：把内核与比对器**一起**改回错的写法，342 项里 **341 项照旧全绿，只有独立预言机断言变红**。

04 里 taibu 的排盘层与本项目**同源 iztro**，`bySolar(...)` 调用逐字相同——所以那一层能验证的只是「各自的集成层」，不是「排得对不对」。真太阳时均时差公式两边也**逐字相同**，同样不能互证。

**判断一个交叉验证有没有价值，先问：它和被测对象共享了多少计算路径。**
