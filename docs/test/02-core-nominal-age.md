## 一、结论

**大限年龄口径混用**：`currentAge` 用**周岁**，而 `daXianAge` / `daXians[].startAge` 用**虚岁**。两者域不同、公式却同形。

最初报告的「每个大限的第一年错位」是**低估**——经子代理扩大采样后修正为：

> **年龄数字本身几乎常年是错的**——实测 **1872 / 1872 = 100%**。

「宫位错位率 ~10%」只是它的**部分可见后果**，不是错误发生率。

## 三、为什么测试套件没测到

**三层同源，必然失明。**

### 1. 比对器复用了内核的同一个公式

`test/lib/compare.mjs:80-82`（修复前）：

```js
export function expectedAge(birthYear, now = new Date()) {
	return now.getFullYear() - birthYear;   // 与 algorithm.ts:148 一字不差
}
```

内核是 `currentYear - year`，测试是 `now.getFullYear() - birthYear`。**同一个公式，同源同错**。比对器拿错误年龄做期望值，内核拿错误年龄算结果，两者必然相等 → `diffs.length === 0` → **测试绿着放行**。

### 2. 期望值本身是用错误年龄找的

`compare.mjs:160-164` 拿到那个错误年龄后，直接用它反查大限：

```js
const age = expectedAge(actual.birthInfo.year, now);
const expIdx = bD.findIndex(d => age >= d.startAge && age <= d.endAge);
```

期望值就是错的，自然"无差异"。

### 3. 不变量测试只管结构，不管「当前该走哪一步」

`invariants.test.mjs:169-203` 的大限测试断言的是：12 步、宫位不重复、每宫 `daXianAge` 与区间一致。这些全是**结构不变量**，跟 `currentDaXianIndex` 该指向哪一步无关。

而 `chart.test.mjs:74-91` 那条漂移测试，证明的是「期望值没照抄样本快照」，**不是**「期望值算得对」。

### 这不是疏漏，是套件自己写明的边界

`test/chart.test.mjs:7-8` 开头就声明了：

> ⚠️ 这套测试是**回归锁定 / 跨版本差分**，不是独立正确性证明：样本与本项目内核同源（都调 iztro 的 `bySolar`），**两边一起错的地方测不出来**。

这个 bug 正好是"两边一起错"的典型。但 `test/README.md` 的「样本覆盖不到的盲区」表只列了 6 处，**没有列「大限年龄口径」**——它是套件里一条**未被登记的盲区**。

### 实测演示

2000 年生、2023 年排盘（虚岁 24，福德宫大限首年）：

```text
现有测试 expectedAge() = 23  → 期望大限落在【父母】  ← 错的
紫微虚岁（正确）       = 24  → 正确大限应是【福德】
```

## 四、内核来源追溯：逐字继承，不是本项目引入

与上游 `reference/ziwei-doushu/lib/ziwei/algorithm.ts` 逐行对比，**逻辑零差异**：

| | 上游 | 本项目 |
| --- | --- | --- |
| 年龄 | `:114` `const currentAge = currentYear - year;` | `:148` 一字不差 |
| 大限匹配 | `:161-163` `dx => currentAge >= dx.startAge && currentAge <= dx.endAge` | `:197-199` 一字不差 |
| 宫位标记 | `:117` `currentAge >= p.daXianAge[0] && ... <= p.daXianAge[1]` | `:151` 一字不差 |

两边该段各约 75 行做归一化 diff，**全部差异只有代码风格**——引号 `'` → `"`、缩进两空格 → tab、等号对齐空格：

```diff
10c9
< const currentAge  = currentYear - year;      ← 上游（两个空格对齐）
---
> const currentAge = currentYear - year;       ← 本项目（格式化后）
```

**上游也没有任何补偿**：前端 `components/` 与 `app/` 下 `currentAge` 一次都没出现（grep 为空），上游 UI 只用 `currentDaXianIndex` 与 `isCurrentDaXian`，直接消费那个错误值，**没有 +1 修正**。所以上游线上站点在大限首年同样会把大限高亮到前一个宫位。

**附带发现**：上游 `algorithm.ts:159` 躺着注释 `// 宫干自化已下线（倪师不主张飞星派宫干自化论）`，本项目 `:195` 有完全相同的注释——**这条也是继承的**。说明上游本身就是按三合派立场写的。

**对修复的意味**：不是本项目引入的回归，但修复是正当的——`CLAUDE.md` 写明内核「在本项目内独立演化……不存在需要同步的副本」，本项目不是上游的镜像。代价是产生一处**与上游的有意分歧**，若日后上游修了这个问题，本项目需要知道「我们已经修过了」。

至于上游跑了这么久没被发现：错位只发生在每个大限的首年（10 年中的第 1 年），用户很少精确意识到「我今年刚好虚岁 24」。

## 五、子代理扩大采样后，推翻了我先前的两个结论

| 我之前的说法 | 实情 |
| --- | --- |
| 「只影响**大限首年**」 | ❌ 只对 offset=1 成立。**春节前出生的人 offset=2，每步大限错两年** |
| 「10 年里有 1 年错位」 | ❌ 那是**宫位**错位率。**年龄数字本身几乎常年是错的**——实测 1872/1872 = **100%** |
| 「对当时的解读无影响」 | ✅ 这条仍成立（2026 虚岁 27 稳落 `[24,33]` 中央） |

我把「宫位错位率」误当成了「错误发生率」。

### 独立复跑验证的事实

| 事实 | 验证 |
| --- | --- |
| **虚岁以正月初一为界** | ✅ iztro 虚岁在 2026-02-17 从 36 跳 37，项目恒 36 |
| **年龄算错是常态** | ✅ n=1872 全部算错（100%） |
| **大限错位率 ~10%** | ✅ 实测 9.5%（子代理报 9.84%） |
| **错位率随时辰剧烈波动** | ✅ 实测 0%–20%（时辰 4 为 0%，时辰 8 为 20%）——**不是均匀的 1/10** |
| **春节前出生 offset=2** | ✅ 1990-01-05 生（农历 1989 年 12 月）：iztro 虚岁 38，项目 36 |
| **春节后出生 offset=1** | ✅ 1990-05-15 生：iztro 37，项目 36 |
| **童限误判** | ✅ 完整复现 |

### offset 的完整刻画

```text
春节后出生：元旦~春节前 → offset 0（正确）；春节~年末 → offset 1
春节前出生：元旦~春节前 → offset 1；      春节~年末 → offset 2
```

所以 `currentAge` 在**春节前出生者身上全年都错**（offset ∈ {1,2}），春节后出生者约 87% 的时间错。

### 童限误判：同一份输出自相矛盾

```text
大限：2-11岁 命宫(酉) | 12-21岁 兄弟(申) | ...
当前年龄：1岁 · 当前大限：—
```

`2025-03-15` 生的孩子，iztro 虚岁 2（正落 `[2,11]` 首年），项目算成 1 → 掉出区间 → 判定「未起运」。**大限表从 2 岁起步却说此人不在任何大限。**

## 六、同族问题：`--liunian` 默认值

另一处**独立的**、同族的口径问题：

```text
2026-01-05 → 农历 2025年冬月十七，农历年干 = 乙
而 CLI 默认 liuNianYear = new Date().getFullYear() = 2026 → 年干 丙
```

在**元旦到春节**之间排盘，流年四化会用一个**还没到来的年干**。`--liuyue` 由它派生，一并继承。

## 七、最严重的后果

`cmdAnalyze` 取到错误大限后，会把**那个错误的宫**当作「当前大限宫」做整宫详批（主星、吉煞、三方四正）。

> **这不是数字偏差，是论断对象错误**——解读文本会围绕一个错误的宫位展开十年运势。

## 九、怎么证明修对了（而不是测试跟着一起错）

核心风险是**同源同错**，所以修复必须自证。

**1. 修复前的两个前提，先验证过**

- `lunar-lite`（iztro 用的）与 `lunar-javascript`（本项目用的）对农历年判定：2358 个日期跨 1930–2060 正月初一前后，**完全一致**
- 算出的虚岁 vs iztro `horoscope().age.nominalAge`：7/7 全中，含正月初一当天=37 / 除夕=36

**2. 独立预言机核对（59 条：7 年份 × 5 时辰 × 2 性别 + 春节边界日）**

| 检查项 | 修复后 | 旧公式 |
| --- | --- | --- |
| `currentAge` = iztro 虚岁 | 0 / 59 不符 | **59 / 59 全错** |
| 大限区间与宫支 | 0 / 59 不符 | — |
| `isCurrentDaXian` 标记 | 0 / 59 不符 | — |

**3. 反向实验**——把内核与比对器**一起**改回周岁（复现 bug 潜伏时的状态）：

> 342 项里 **341 项全绿，只有新加的那条预言机断言变红**。

这正是它当初没被发现的原因，也说明新断言是**唯一**能抓住它的。

**行为对照：**

- 1990-05-15 男：`当前 36岁` → **`当前 37岁`**（落在 36-45 大限内）
- 2025-03-15 童限案例：`当前年龄：1岁 · 当前大限：—`（误判未起运）→ **`2岁 · 命宫`**，与 `2-11岁` 大限自洽

**4. 顺带核实的两处**

- 童限与女命案例与 taibu 对齐（女命逆排后 36-45 从男命的田宅(卯)移到子女(酉)，两边都给出 **乙酉**）。**注意 taibu 的虚岁取自 iztro 的 `horoscope.age.nominalAge`，与本项目的预言机是同一个函数**——所以这次对齐证明的只是「本项目与 iztro 对齐了」，见 [04](04-crossval-taibu.md) 的同源讨论
- 核实文档时发现 `SKILL.md:148` 写「`chart.palaces` 按地支 0-11（子…亥）排序」，但实测是 `2,3,…,11,0,1`（**寅起**）——`CLAUDE.md:103` 记的是对的，两份文档互相矛盾。这条会让模型按「子起」索引宫位而张冠李戴，已改正
