## 二、做得好的（行为标准特性，实测确认）

### 1. 流程闭环

- 工作流三步 ↔ output-contract 五节**一一对应**（workflow:80 明确声明"五节与这五步一一对应"）；
- 合盘五步法（guide）↔ 合盘输出形态 7 步（output-contract）↔ `synastry` 命令输出字段，三级对齐；
- 排障文档按"遇到什么错 → 读哪个文件 → 怎么处理"组织，实测报错文案全部标注"实测原文"（可追溯文化，防文档编造）。

### 2. 防幻觉设计（这是全文档体系最亮的部分）

| 机制                                                          | 位置               | 作用                       |
| ------------------------------------------------------------- | ------------------ | -------------------------- |
| "每个断语都能指回 CLI 数据（星/宫/格局名），**不凭记忆加星**" | output-contract:42 | 强制从数据到结论，堵死编造 |
| "星级定档……**注明这是你的裁量结论——CLI 不输出分数**"          | output-contract:79 | 区分机器输出与人工裁量     |

| 知识源映射表（需要什么 → 读哪里）                             | workflow:66-74     | 用文件路径替代记忆         |
| "识别为空 → 一句「未成格局」带过，**不硬凑**"                 | output-contract:22 | 防过度解读                 |

### 3. 口径锁死

虚岁（不换算周岁）、第 8 宫「交友宫」非「仆役」、晚子时两盘对照必须转达、真太阳时跨午夜改期是正确行为——全部以"硬约束"姿态写入，防 agent 踩坑。

### 4. 防飞星误用

synastry-guide 顶部 ⚠️ 声明"读到「飞化」不要去找 mutagen.ts 的飞星工具（已删除）"——连方法论文档都嵌了体系护栏。

## 四、流程合理性评估

**总体成立**：渐进披露（触发 → 总纲 → 按需细则）与 agent 上下文经济一致；排障分流（troubleshooting 管启动/参数、synastry-troubleshooting 管合盘）职责不重叠。

**两个缺口**：

1. **口径转达无强制检查点**：output-contract 把"口径提示转达完才进入解读"列为硬约束，但工作流三步没有对应的步骤卡点——靠 agent 自觉。建议 workflow 第 3 步加一行"先转达口径提示再解读"（与 output-contract 呼应，形成流程闭环）。
2. **事业合作合盘无挂点**（D4）：要么在 output-contract 加"合作合盘形态"，要么在 synastry-guide 第八节注明"仅用户明确问事业/合作时启用，按流年或聚焦形态给出官禄/兄弟/交友宫分析"。
