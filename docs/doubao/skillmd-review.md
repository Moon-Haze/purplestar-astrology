## 一、做得好的地方

### 1. 三级渐进披露（最亮点的设计）

| 层级      | 载体                      | 职责                                                                                               |
| --------- | ------------------------- | -------------------------------------------------------------------------------------------------- |
| L1 常驻   | frontmatter `description` | 触发匹配用，24 小时在线，约 240 字 + 23 触发词 + 排除项                                            |
| L2 触发后 | SKILL.md 正文（137 行）   | 四必问铁律、工作流三步、输出契约、体系硬约束、命令速查                                             |
| L3 按需   | `references/`（6 个文件） | workflow / output-contract / options / synastry-guide / synastry-troubleshooting / troubleshooting |

**价值**：描述常驻但不冗长；正文控制篇幅只放"必须知道"的；细节下沉按需读。这是 agent 场景正确的知识组织方式——不会让每次触发都加载全量知识。

### 2. frontmatter 排除项明确

`不要用于八字/四柱/子平（不排八字）、塔罗、占星` —— 主动声明**不是**什么，比只声明是什么更能防止误触发。排除项与「本技能不做的事」节（§「本技能不做的事」）首尾呼应。

### 3. 铁律先行：四个必须问清的输入

正文第一节就是「铁律：四个必须问清的输入」表格（出生日期 / 出生时间 / 性别 / 晚子时钟点），每条给出**缺失时怎么办**的可操作路径（`--lunar` / `--branch 5` / "按子时试排"标注）。排盘错一个输入整盘皆错，把追问纪律放在最前是正确优先级。

### 4. 真太阳时跨午夜：把"正确行为"讲成知识，防误报 bug

「真太阳时跨过午夜时，出生日期会跟着改——这是正确行为，不是 bug」——主动解释了输出日期可能与输入差一天的现象（喀什凌晨回退、哈尔滨深夜顺延），并给出转达话术。这类"看起来像 bug 的正确行为"是 agent 最容易搞错的点，提前标注价值极高。

### 5. 负向约束（体系硬约束）：三合派 vs 飞星派

- 明确列出**已下线的飞星派工具**（宫干自化 / 大限四化取宫干 / 来因宫）
- 明确指出 `mutagen.ts` 只提供三层四化（生年 / 流年 / 流月），**飞星派函数已删除**——不是改名不是移走，全仓零调用
- 关键细节：`selfMutagen` / `Decadal.mutagen` 字段仍在，那是**刻意留下的绊线**，selftest 与 `test/school.test.ts` 的断言盯着它们不被填回——「存在不等于该用」
- 引用倪师原话（"大道至简，飞星飞来飞去太复杂"）增强体系立场可信度

这是**罕见的技能设计**：连"代码里有什么历史残留、为什么残留"都写进文档，防止后续 agent 把绊线字段当功能捡回来。

### 6. 篇幅契约

`全盘解读 800–1500 字；单问某宫或 --focus → 300–600 字` —— 明确量化，防输出无限膨胀。同时「年龄一律虚岁，不要自行换算成周岁（换算即错，且会连带说错当前大限）」——把最容易犯的数值错误单列硬约束。

### 7. 防文档-代码漂移断言

selftest 里有「SKILL.md 提到的旗标都在声明表里」的断言——**文档与代码互相盯着**，改一边另一边会红。这是很多项目缺的：文档漂移到最后没人信。

### 8. 命令速查 + references 指引闭环

正文末尾命令速查表（6 命令）+ 高频参数一句话，细节（英文主名/拼音别名/位置参数/`--config`/`--charts`）全部指到 `references/options.md`。正文短、全量在 references。

## 四、结论

**SKILL.md 是高分设计**：渐进披露、铁律先行、负向约束、防漂移断言四件事同时做到，且每个论断都有实测支撑。剩余 R1–R4 均为**可读性 / 一致性打磨**，不影响正确性——且改动 SKILL.md 需同步留意 selftest 的文档-代码一致性断言（改旗标描述若与声明表不一致会挂测试），建议作为一次性整理任务，与 R2（别名收敛）合并处理。
