## 三、做得特别好的地方

1. **防御"假绿"的自觉贯穿始终**：处处有空转保护——每个格局断言要求正反两侧都有样本命中，否则报错；每组合盘样本配样本守卫断言；`NO_HIT_IN_FIXTURES` 显式登记空转项。

2. **"独立预言机"方法论**：期望值刻意不走被测实现路径：
   - 虚岁用 `lunar-typescript` 独立换算 + iztro `horoscope()` 外部预言机
   - 宫名用两条不读映射表的独立路径（iztro 直连词法 + 偏移算术）
   - 流年/流月四化用口诀表 / lunar 年柱 / 万年历固定向量三条独立路径
   - 格局识别按宫名走、实现按地支算术走——两条路径分岔

3. **白名单机制严谨**：不是跳过字段，而是"全等比对 + 显式白名单"，只放行 brightness 单字段在特定宫位的差异，每条写明 `cause` 根因。白名单之外任何差异都失败。

4. **维护性极好**：`README.md` 是活文档，明确写了效力边界、升级流程、维护点，并记录了历史上"比对器与内核同源同错、341 项全绿"的事故。

## 四、可留意的点（非缺陷）

1. **层 2 CLI 测试偏慢**：39 项花 126 秒，最慢 5 项里 4 项是 CLI 层（真太阳时 19.7s、--focus 15.4s、合盘 13.4s、性别护栏 12.9s）。原因是每个用例起约 0.6 秒的子进程，已有 `memo()` 缓存优化。

2. **invariants.test.ts 单文件超长（899 行）**：含 70 个格局预言机表，与 `patterns.ts` 强绑定，新增格局须同步补预言机，是持续维护负担。

3. **口径争议被诚实记录**：火贪/铃贪格局注释记录了"32 次命中里 12 次煞星照不到命宫"的争议，照实现复刻而非照理想口径。

4. **fixtures 覆盖段有限**：基准只覆盖 1924–1983（300 条抽样），其余年份段依赖 `tools/` 全量脚本手动核验。

## 五、总体评价

这套测试把"**如何证明一个排盘内核没有静默排错盘**"当成工程设计来做：分层隔离基准依赖、用独立预言机对抗同源同错、用空转保护对抗假阳性、把效力边界写进文档。**工程质量属于上游水准，可作为其他项目的测试范式参考。**
