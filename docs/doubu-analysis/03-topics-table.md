# 03 · topics 表分析

**日期：** 2026-09-25
**分析对象：** DuckDB 中的 `topics` / `topic_dict` / `topic_lines` 三张表

---

## 一、topics 表是干什么的

**一句话：它是排盘结果的人性化命理解读文本，也就是"每个命盘该怎么说"的成品文案。**

具体是 **13 个主题维度**的紫微斗数论断文字，每个主题对应一个宫位，由 `db-analysis.ts`（2271 行，含 14 主星 × 各宫位语境 + 四化 + 三方四正 + 大限/流年/流月）动态生成。

### 13 个主题

| 主题 key    | 中文       | 对应宫位 |
| ----------- | ---------- | -------- |
| overview    | 命格总览   | 命宫     |
| personality | 性格特质   | 命宫     |
| love        | 感情婚姻   | 夫妻宫   |
| career      | 事业职业   | 官禄宫   |
| wealth      | 财富运势   | 财帛宫   |
| health      | 健康状况   | 疾厄宫   |
| family      | 兄弟合伙   | 兄弟宫   |
| children    | 子女缘分   | 子女宫   |
| move        | 迁移外出   | 迁移宫   |
| friends     | 人际贵人   | 交友宫   |
| home        | 田宅不动产 | 田宅宫   |
| spirit      | 精神福德   | 福德宫   |
| parents     | 父母长辈   | 父母宫   |

每条样本的 `topics` 字段是这 13 个主题拼成的长文本，单条约占原语料体积 90%，是整库体积的绝对大头。

## 二、内容长什么样

它是**"倪海厦《天纪》体系"的星曜命理知识库**，按主星 × 宫位语境组织。例如"紫微守命"命宫段（节选）：

> 紫微帝星守命，格局高贵，天生具有领导气质与王者风范，一生以"贵"为主轴……倪海夏言：「紫微守命，贵而不富，需禄配合方全美」……命宫紫微者，自尊心极强，主观固执，好面子，领导欲旺盛……

每颗主星（14 颗）有：

- **12 宫语境**（命宫/兄弟/子女/迁移/交友/田宅/福德/父母/夫妻/官禄/财帛/疾厄）
- **四化语义**（禄权科忌各自补充）
- **summary 深描**（按男女命分开的 overview/love/career/wealth/health 长段）
- **topic_mods**（亮度庙旺利陷 + 四化时的动态定制文案）

生成方式不是查静态库，而是 `getTopicAnalysis()` **基于整张盘动态推算**：取主宫主星（空宫借对宫）、算三方四正、叠加当前大限/流年/流月，拼出论断。

## 三、重要的新情况

最近更新把 `db-analysis.ts` **拷进了本仓内核**（`scripts/ziwei/`），且 `scripts/cli/commands.ts` 新增 `topic` 命令直接调用它：

```bash
node scripts/purple-star.ts topic --date 1990-05-15 --branch 5 --gender male --topic love
```

`selftest.ts` 里也有自检用例。也就是说——**topics 的"生成能力"现在已在 CLI 里活着，运行时动态算出，根本不依赖数据库里的 topics 表。**

## 四、对压缩分发的直接影响

| 原本以为                              | 实际情况                                                           |
| ------------------------------------- | ------------------------------------------------------------------ |
| topics 表是数据主体，删了就没解读能力 | ❌ 解读能力在 `db-analysis.ts` 代码里，运行时动态生成，不需要那张表 |
| 删 topics 表 = 丢失功能               | ✅ 删表零功能损失，只少了"预生成的成品文本"                         |

**结论：DuckDB 里那三张 topics 表（673 万行、占 90% 体积）对项目完全多余**——数据文件是被淘汰的旧载体。项目现在走"代码生成解读"的新路线（`getTopicAnalysis`），那三张表是旧"预存文本"路线的历史遗留。压缩分发时可直接删掉重建，只留 `samples` + `palaces`，体积从 1.76GB 砍到约 150–300MB，且不损失任何功能。
