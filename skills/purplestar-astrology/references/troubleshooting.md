# 排障：脚本报错与回归

本文件是 `SKILL.md`「若脚本报错」一节的展开——**遇到报错、或要改这个 skill 时才读**。

## 启动期报错

| 报错                                                | 原因与处理                                                                                                                              |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `[ziwei 启动失败] 找不到排盘内核`                   | skill 目录不完整，`<skill>/scripts/` 下的内核缺失（拷贝时漏带）。从本仓库补回 `scripts/ziwei/` 整个目录（合盘与古籍检索的内核各归它们自己的 skill，本技能**不需要**），或用 `ZIWEI_ROOT=<含 ziwei/ 的目录>` 指定内核位置。 |
| `[ziwei 启动自检失败]`                              | 内核被重构、关键导出改名或删除。核对 `scripts/cli/` 各模块的 import 列表与 `scripts/` 下内核的实际导出是否对得上。                       |
| `Cannot find module 'iztro'` / `'lunar-typescript'` | 依赖未装。**看报错里的「当前内核根」**，在该目录下 `npm install`。                                                                       |
| `registerHooks is not a function` 或 TS 语法报错    | Node 版本过低，需 ≥ 22.15（本项目开发环境为 v26）。                                                                                     |

## 确认跑的是哪一份内核

`purple-star.ts` 按**两级优先级**定位内核 —— `ZIWEI_ROOT` 环境变量优先，未设则用技能自带的 `<skill>/scripts/`。

`selftest` 输出的**第二行**（形如 `内核根：<路径>`）就是当前生效的那一份，交付解读前据此核对。

## 参数报错

| 报错                                   | 原因与处理                                                                                    |
| -------------------------------------- | --------------------------------------------------------------------------------------------- |
| `缺少性别：需 --gender male\|female`   | 没给性别。性别决定大限顺逆，**不要替用户猜**，直接追问。取值非法（如 `--gender xyz`）同样报错。 |
| `未收录城市`                           | 改用 `--lng` 直接给经度。                                                                     |
| `未知参数 --dtae。最接近的是 --date。` | 旗标拼错。提示里给的是**最接近的合法旗标**，照它改。                                          |

## 回归：改完之后跑什么

改完本技能或升级依赖后，**先跑 `selftest`**：

```bash
node scripts/purple-star.ts selftest
```

它覆盖农历换算、真太阳时、晚子时等价性、城市容错、性别护栏、排盘不变量、三合派约束、知识源可用性、参数面与 `SKILL.md` 的一致性。**全绿再交付解读。**

**要更彻底的回归，再跑 `npm test`**（在仓库根）：拿 300 条真实盘逐字段对标排盘结果，测的是 `selftest` 那几条固定样例覆盖不到的行为漂移。两者分工不同，都要跑。测试的性质、效力边界与「升级 `iztro` 后怎么办」见仓库根的 `test/README.md`。

**改过 `scripts/` 下 `.ts` 的类型标注，再跑 `npm run typecheck`**（必须 0 错误）。它只保证类型自洽，不保证类型标得对——用 `any` 绕过报错它一样全绿，所以内核里不使用 `any`。

⚠️ 本 skill 是**源**：`skills/` 下另外两个 skill 的内核是从这里切出去的副本。改内核一律改这里，改完在仓库根跑 `npm run sync:skills` 同步出去，再跑 `npm test`（层 6 会逐字节核对副本）。
