# 紫微斗数合盘与合婚

**本技能不排盘。**两张命盘由 `purplestar-astrology`（排盘解读）产出，本技能只读它的 `analyze --json` 输出做合盘——没有排盘引擎，也不依赖 `iztro`。因此**合盘永远是两步**：先在那个技能里排两张盘，再回到本技能合参。

本技能真正自有的资产只有两份，且**只住在本技能里**（源 skill 里没有对应物）：

- 夫妻宫断语与四化断语的**权威文件** `scripts/ziwei/synastry-knowledge.ts`；
- **合盘方法论与评分标准** [references/synastry-guide.md](references/synastry-guide.md)。

**改这两份就在本技能里改，没有「同步」这回事。**反过来，`scripts/boot-hooks.ts` 是 `purplestar-astrology` 的逐字节副本（`ziwei/types.ts` 与 `ziwei/citation-guard.ts` 也是），改它们一律改源再 `npm run sync:skills`——就地改会被同步器覆盖，仓库的层 6 断言也会先变红。

⚠️ **`scripts/cli/args.ts` 不在此列**（2026-09-27 换解析引擎）：它不再是源的副本——源那份仍由 `cac` 驱动，本技能与 `purplestar-classics` 用的是 Node 内置的 `node:util` 的 `parseArgs` 版，**两份派生副本逐字节相同，以 `purplestar-classics` 那份为准**。就地改本技能这份会被层 6 的断言当场抓住。**本技能与古籍检索 skill 因此都是零依赖**，不需要 `npm install`。

**本技能只做双人合盘。**用户要的是「排一张盘」「解读我的命盘」→ 那是 `purplestar-astrology`（排盘解读）的活；「查一句古诀的原文」→ `purplestar-classics`（古籍检索）。**单人解读用本技能是错的**——本技能的命令不输出格局、主题论断与分宫详表，硬做只会得到一张残缺的解读。

## 路径约定

本 skill 的根目录就是 **SKILL.md 所在目录**，其下是 `scripts/`（CLI + 合盘内核）、`references/`（按需加载的参考文档）、`package.json`。

下文所有命令中的 `node scripts/purple-star.ts` 都**相对于 skill 根目录**。执行前 `cd` 到该目录即可：

```bash
cd <SKILL.md 所在目录> && node scripts/purple-star.ts synastry --a-chart /tmp/a.json --b-chart /tmp/b.json
```

脚本本身可从**任意 cwd** 运行（内核按脚本自身位置定位，不依赖 cwd），所以 `cd` 只是为省去拼长路径。

⚠️ 引用**另一个 skill** 时不要写相对路径——那是本 skill 内部的约定，装到 `~/.claude/skills/` 之后跨 skill 的相对路径并不成立。下面用 `$PURPLESTAR` 指代 `purplestar-astrology` 技能的根目录。

## 铁律：四个必须问清的输入（双方各一份）

合盘要两张盘，任一方错一个输入，那一方的盘全错，合盘结论随之作废。用户没给全时**必须追问**，不要猜：

| 输入                           | 为什么关键                                | 缺失时怎么办                                                                                      |
| ------------------------------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **出生日期**（双方）           | 定命宫、五行局、紫微位                    | 必问。公历还是农历要问清（农历还要问闰月）——**不要把农历当公历传**，那会排出一张完全无关的盘      |
| **出生时间**（双方）           | 差一个时辰（2 小时），命宫与十四主星全变  | 只知时辰名（如「巳时」）→ 可以；完全不知 → 告知用户需提供，或明确标注「时辰不详，以下按子时试排」 |
| **性别**（双方）               | 决定大限顺逆（男女大限可差 80 年）        | 必问。排盘方已强制该参数缺失即报错，不会替你猜                                                    |
| **23:00–23:59 出生的具体钟点** | 子时横跨两日，早/晚子时是**两张不同的盘** | 见下方「晚子时」专节。任一方给了 `23:xx`，必须读排盘方给出的差异提醒并转达                        |
| **出生地**（双方）             | 决定真太阳时校正量                        | 强烈建议问。不给则按东经 120° 不校正，排盘方会提示「结果可能有偏差」，你要把这句话转达给用户      |

这五项**全部由 `purplestar-astrology` 消费**——对应的参数怎么写，读那个技能的 `SKILL.md` 或它的 `help`。**本技能刻意不复制那份参数表**：复制一份出来就有了两处需要手工同步的真相，源那边改个参数名，这里会静默漂移。

## 工作流

### 第 1 步：在 purplestar-astrology 里排两张盘

```bash
PURPLESTAR=<purplestar-astrology 技能根>
# 参数面（日期 / 时间 / 性别 / 出生地）见那个技能的 SKILL.md
node "$PURPLESTAR/scripts/purple-star.ts" analyze <甲方的出生信息> --json > /tmp/a.json
node "$PURPLESTAR/scripts/purple-star.ts" analyze <乙方的出生信息> --json > /tmp/b.json
```

⚠️ **必须是 `analyze`，不是 `chart`**。两条命令都输出命盘，但只有 `analyze` 的输出带**四化落宫**与**排盘依据**——缺了前者的「生年四化入夫妻宫」那节会整个空掉，缺了后者则无法转达真太阳时与晚子时提示。拿 `chart` 的输出来顶替会被本技能当场拦下。

⚠️ 出生信息若含空格或中文，命令里该加引号就加（如城市名），别让 shell 拆词。

### 第 2 步：合盘取数

```bash
node scripts/purple-star.ts synastry --a-chart /tmp/a.json --b-chart /tmp/b.json
```

`synastry` 一次给出合盘解读所需的全部结构化数据：双方命宫/夫妻宫/福德宫、天作之合对应关系判定、夫妻宫完整断语、生年四化入夫妻宫、桃花孤克星，以及**排盘依据的转述**（真太阳时校正量、跨午夜改期、晚子时标记、出生地解析说明）。

**一次调用即可开始解读，不要分两次跑。**

### 第 3 步：按需深入知识源

CLI 已给出双盘数据与断语。需要展开论证时，**直接读这些文件**（它们是本技能的权威依据，不要凭记忆编造）：

| 需要什么                                                 | 读哪里                                |
| -------------------------------------------------------- | ------------------------------------- |
| 十四主星在夫妻宫断语、四化入夫妻宫                       | `scripts/ziwei/synastry-knowledge.ts` |
| **合盘方法论与评分标准**（五步法、缘分类型、婚期三层法） | `references/synastry-guide.md`        |

**评分标准与完整方法论不在 `synastry` 的输出里**——它们是恒定静态文本（与「这一对是谁」无关，排谁的盘都是同一份），住在 [references/synastry-guide.md](references/synastry-guide.md)，`synastry` 末尾只留一行指针。因此：

- 要在解读里给这段关系**定档（几星）**时，读该文件的「评分标准」节；
- 要展开夫妻宫断语之外的方法论（五步法、缘分类型、婚期三层法）时，读同文件的「合盘分析核心框架」节。

⚠️ 该文件里「四化飞化互参」一类表述是**方法论层面的技法描述**，不是让你去调飞星派的工具——本项目已下线宫干自化与大限四化取宫干（见下文「体系硬约束」）。

⚠️ **四化体系与星曜释义的实现在排盘方那边**，本技能不持有（`ziwei/sihua.ts`、`ziwei/constants.ts` 不在本技能里）。合盘只用**双方生年四化**互落对方宫位，而这项数据由 `analyze --json` 的 `nativeSiHua` 直接给出——不需要、也不该去别处重算。

### 第 4 步：合参解读

解读合盘时**必须双宫联参**（倪师核心断法）：

> 看婚姻，光看夫妻宫，大错特错，一定要同时看福德宫。

夫妻宫看配偶星性与互动模式，福德宫看感情能否长久。夫妻宫好而福德宫破，"散"。

按这个顺序展开，不要跳步（下方输出契约的四节与这四步一一对应）：

1. **命宫 × 命宫定基调** —— 双方命宫主星互动：性格底色合不合、谁带动谁。
2. **夫妻宫 × 福德宫联参** —— 展开 `synastry` 给出的断语。这是本技能的核心，不能跳过福德宫只论夫妻宫。
3. **四化互动定着力点** —— 双方生年四化互落对方宫位：谁的禄入谁的关键宫（滋养从哪来），谁的忌落何处（摩擦在哪）。
4. **结论落到相处经营的具体行为** —— 不要停在术语堆砌。

### 合盘输出契约

合盘解读与全盘解读共用形态硬约束（直断、虚岁、数据锚定、术语白话、口径转达），结构按此模板——**章节、顺序、命名固定**，`<>` 为待填槽位：

```markdown
## 合盘解读 · <甲方命宫主星> × <乙方命宫主星>

**甲方**：<性别>，<公历日期 钟表时刻>（<城市>）→ 真太阳时 <时辰> · <X>局 · 现行<大限宫>大限（虚岁 <N>）
**乙方**：<同一格式>

**总评**：<2–3 句，先给天作之合判定结论与关键张力点。>

### 命宫 × 命宫

<双方命宫主星互动 2–3 句：性格底色合不合、谁带动谁。>

### 夫妻宫 × 福德宫（双宫联参）

<展开 synastry 输出的断语，3–5 句。夫妻宫看配偶星性与互动模式，福德宫看能否长久——夫妻宫好而福德宫破，"散"。>

### 四化互动

<双方生年四化互落对方宫位，2–4 句：谁的禄入谁的关键宫（滋养从哪来），谁的忌落何处（摩擦在哪）。>

### 综论与建议

<2–4 条，落到相处经营的具体行为。>
```

**形态硬约束**：

- **篇幅**：600–1200 字。
- **表格**：全文 ≤ 2 张，只用在四化互动节；其余内容用短段落与列表。
- **术语**：首次出现配一句白话。每个断语都能指回 CLI 数据（星 / 宫 / 格局名），不凭记忆加星。
- **语气**：直断——先给结论再补依据；不好看的结论也直说，不粉饰。
- **年龄**：一律虚岁，报 CLI 给的数，不换算周岁。
- **口径转达**：排盘方写进 JSON 的口径提示（真太阳时校正量、跨午夜改期、晚子时标记、城市歧义候选）由 `synastry` 复述在基本信息行或紧随其后，**转达完才进入解读**。

## 排盘依据：本技能只转述，不重算

真太阳时校正、跨午夜改期、出生地解析、晚子时标记——这些**全在排盘那一刻定死**，随 `analyze --json` 一起交过来（`basis` 与 `lateZi` 两个字段）。本技能不做任何出生信息解析，因此：

- 输出里的「真太阳时校正」栏是**排盘方算的**，直接转述。
- 日期与你给排盘方的输入**可能差一天**（真太阳时跨过午夜时会回退/顺延）——这是正确行为，不是 bug，排盘方会写明，照实转达即可。
- 若真太阳时口径需要讨论（默认只做经度校正，加不计均时差），那是**排盘那一步**的事：回到 `purplestar-astrology` 用另一种口径重排一张，而不是在本技能里找开关。

### 晚子时：子时横跨两日，这是个真陷阱

任一方 `23:00–23:59` 出生时，两种口径排出的是**两张完全不同的盘**（命宫主星、紫微位、格局组全变），不是微调：

| 口径              | 含义                             |
| ----------------- | -------------------------------- |
| **当日早子时**    | 按出生当日的农历日数安星（默认） |
| **晚子时·算次日** | 子时归次日，按次日的农历日数安星 |

已验证的等价关系：**`timeIndex 12` ≡ 次日 `timeIndex 0`**（命盘逐宫完全一致）。

**口径在排盘那一步就定死了**，本技能只读 `lateZi` 标记并转述：

- `lateZi.candidate` 为真时，输出会给出该方的晚子时提醒 —— 你**必须**把这段读出来，不能在解读里装作没这回事。
- 逐字读提醒里的两组「紫微落 X · 命宫主星 Y」，据此向用户说明差异有多大，并**建议其确认具体钟点**。
- ⚠️ **该方命盘会整体改变，合盘结论需重跑** —— 晚子时不是只动一方的一个字段，它会推翻已经算出的天作之合判定与夫妻宫断语。别在旧结论上打补丁。
- 若用户确认为 23:00 后出生且要求按传统口径，**回 `purplestar-astrology` 用晚子时口径重排该方**，拿到新的 JSON 再重跑本技能。

⚠️ **不要**在没有提示的情况下自行替用户选口径。选错口径的合盘，等于给错两个人算命。

## 体系硬约束：三合派，不是飞星派

本项目**严格遵循倪海夏《天纪》三合派**。以下飞星派工具在本项目中已被**主动下线**，你**不得**使用，也不要从代码里把它们捡回来：

- ❌ **宫干自化** —— 排盘内核已停止填充 `Palace.selfSihua`（注释明确："倪师不主张飞星派宫干自化论"）
- ❌ **大限四化取宫干** —— 已停止生成 `daXians[].siHua` / `stemIndex`
- ❌ **来因宫** —— 飞星派追溯法，不使用

⚠️ **陷阱**：飞星派的 `detectSelfSihua` / `findIncomingPalaces` / `getDaXianSiHua` 等函数已于 2026-09-27 从源内核的 `ziwei/sihua.ts` **删除**——不是改名、不是移到别处，全仓零调用点。本技能更彻底：连 `sihua.ts` 都不在切片里，**没有任何四化实现可供误用**，合盘要的四化只有排盘方给的 `nativeSiHua` 一个来源。

但 `types.ts` 里的 `Palace.selfSihua` / `DaXian.siHua` 字段与 `SelfSihuaMark` / `DaXianSiHua` 两个类型**仍在**（本技能持有一份只读的类型契约，见上文），那是**刻意留下的绊线**：断言盯着它们不被重新填回，字段删了就没东西可盯。**存在不等于该用**——用它们解读就是背叛本项目的体系立场。

可用的是：**生年四化**（出生年干）、**流年四化**（当年年干）、**流月四化**。合盘断语用的是双方**生年四化**互落对方宫位。

倪师核心立场（权威声明在源 skill 的 `ziwei/sihua.ts`「体系基准」节）：

> 大道至简——飞星飞来飞去太复杂，不搞这个。
> 命宫为本，三方为用。
> 人事努力 + 地理调整 > 先天命运（2/3 > 1/3）

## 其他已知事实

- **庙旺利陷口径**：排盘方给的 `brightness` 是 iztro 的 7 级塌缩成 3 级——`bright` = 庙/旺，`dim` = 陷/不，**其余（`得`/`利`/`平`）一律 `normal`**。另注意 `brightness` 字段**只给主星填**：`chart.palaces[].stars[]` 是个**扁平数组**（每项带 `type`，取值为 `major` / `minor` / `sha` / `lucky`，**不存在** iztro 原始的 `minorStars` / `adjectiveStars` 这两个键），只有 `type === "major"` 的那 14 颗带 `brightness`，其余三类不带（信息比 iztro 原始输出少，是口径选择不是缺漏）。
- **年龄一律是虚岁**：`currentAge`（当前年龄）、`daXians[].startAge/endAge`、`palace.daXianAge` 三者**同为虚岁**，以**农历年（正月初一）为界** —— 不是生日，也不是立春。数据来自 iztro 的 `decadal.range`。解读时报给用户的年龄就用这个虚岁，**不要自行换算成周岁**（换算即错，且会连带说错当前大限）。
- **童限**：`currentDaXianIndex === -1` 表示此人**尚未起运**（虚岁小于五行局数，如土五局要 5 岁才起运），此时 CLI 的「当前大限」显示 `—`。这是正常的，不是数据缺失——此时按命宫论，不要硬套一个大限。合盘里任一方未起运时，「现行大限」栏会缺一边，照实转达。
- **十二宫顺序**：`chart.palaces` 按**地支数组序**排，实测为 `2,3,…,11,0,1`（**寅起**）——既不是 0-11（子起），也不是宫位顺序（命宫起）。定位某宫请按 `branch` 建索引，**不要依赖数组下标**。
- **知识来源分级**：`synastry-knowledge.ts` 与 `references/synastry-guide.md` 里「倪师说」引号句部分为传统口诀的**风格化转述**，不一定是《天纪》逐字原话，引用下断语须注明口径。

## 若脚本报错

遇到报错、或想确认当前跑的是哪一份内核 —— 读 [references/troubleshooting.md](references/troubleshooting.md)（启动期报错、参数报错、改完本 skill 后的回归方式都在那里）。

⚠️ 但**最要紧的一条留在这里**，因为它报的错**不在本技能身上**：`synastry` 拦下命盘 JSON 时（顶层缺 `chart`、缺 `nativeSiHua`、文件不是合法 JSON），**根因通常是第一步用错了命令**——拿 `chart --json` 的输出顶替了 `analyze --json`。看到这类报错先回去复核那两条排盘命令，别在本技能里找问题。
