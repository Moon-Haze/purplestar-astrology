# 紫微斗数合盘与合婚

本技能的排盘内核与合盘断语全部在 `scripts/` 下（与 CLI 同处一层），**不重复实现任何命理逻辑**——CLI 只是这些模块的访问层。两张盘由 `iztro` + 项目既有算法确定性产出，你只负责**合参解读**。

夫妻宫断语与四化断语的**权威文件是 `scripts/ziwei/synastry-knowledge.ts`，它只住在本技能里**（2026-09-27 拆 skill 时随 `synastry` 命令一并搬来，`purplestar-astrology` 里已没有这份文件）。合盘**方法论与评分标准**另住在本技能的 [references/synastry-guide.md](references/synastry-guide.md)，同为本技能自有。排盘底座（`ziwei/` 下其余模块）是 `purplestar-astrology` 的逐字节副本，改内核一律改那边再 `npm run sync:skills`——**只有上面这两份是反过来的：改它们就在本技能里改**。

**本技能只做双人合盘。**用户要的是「排一张盘」「解读我的命盘」→ 那是 `purplestar-astrology`（排盘解读）的活；「查一句古诀的原文」→ `purplestar-classics`（古籍检索）。**单人解读用本技能是错的**——本技能的命令不输出格局、主题论断与分宫详表，硬做只会得到一张残缺的解读。

## 路径约定

本 skill 的根目录就是 **SKILL.md 所在目录**，其下是 `scripts/`（CLI + 内核）、`references/`（按需加载的参考文档，如 `synastry-guide.md`）、`package.json`（依赖）。

下文所有命令中的 `node scripts/purple-star.ts` 都**相对于 skill 根目录**。执行前 `cd` 到该目录即可：

```bash
cd <SKILL.md 所在目录> && node scripts/purple-star.ts synastry --a-date 1990-05-15 --a-time 09:30 --a-gender male --b-date 1993-08-22 --b-time 14:00 --b-gender female
```

脚本本身可从**任意 cwd** 运行（内核按脚本自身位置定位，不依赖 cwd），所以 `cd` 只是为省去拼长路径。

## 铁律：四个必须问清的输入（双方各一份）

合盘要排**两张**盘，任一方错一个输入，那一方的盘全错，合盘结论随之作废。用户没给全时**必须追问**，不要猜：

| 输入                           | 为什么关键                                | 缺失时怎么办                                                                                                                  |
| ------------------------------ | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **出生日期**（双方）           | 定命宫、五行局、紫微位                    | 公历用 `--a-date` / `--b-date`；**农历直接用 `--a-lunar` / `--b-lunar`**（脚本自动换算，闰月加 `--leap`）。不要把农历当公历传 |
| **出生时间**（双方）           | 差一个时辰（2 小时），命宫与十四主星全变  | 只知时辰名（如"巳时"）→ 用 `--a-branch 5`；完全不知 → 告知用户需提供，或明确标注"时辰不详，以下按子时试排"                    |
| **性别**（双方）               | 决定大限顺逆（男女大限可差 80 年）        | 必问。CLI 已强制：`--a-gender` / `--b-gender` 缺失或非法取值直接报错，不会替你猜                                              |
| **23:00–23:59 出生的具体钟点** | 子时横跨两日，早/晚子时是**两张不同的盘** | 见下方「晚子时」专节。任一方给了 `23:xx`，必须读脚本给出的差异提醒                                                            |

**合盘参数一律在单人参数前加前缀**：甲方的加 `a-`，乙方的加 `b-`。`--a-date` / `--b-time` / `--a-gender` / `--b-city`…全部如此（`--a-branch`、`--a-late-zi`、`--a-lunar` 同）。

⚠️ **漏前缀不会报错，会静默排出一张错盘** —— 这是本技能最容易踩的坑。`synastry` 读的是 `aDate` / `aCity` 这些**带前缀**的键，写成无前缀的 `--date` / `--city` / `--eot` / `--late-zi` 时它们全都读不到，脚本既不报错也不提示，直接按默认值排盘。实测：`--city 喀什` 漏成 `--city`（本应 `--a-city`）后，甲方从「巳时 · 火六局 · 命宫子破军」变成「卯时 · 土五局 · 命宫寅廉贞」——**整盘全变，而输出里一个字都没说**。

唯一有效的无前缀旗标是 **`--json`**（输出选项，与两方无关）。除此之外，凡是描述出生信息的旗标，**每一个都必须带 `a-` 或 `b-`**。敲完命令请逐个复核一遍前缀，再看输出里的「真太阳时校正」栏是否符合预期——校正量为 `+0 分` 而你明明给了出生地，就是漏了前缀。

**出生地**强烈建议一并问（双方各一份）：本项目按**真太阳时**排盘（倪海夏批命即用真太阳时）。给了 `--a-city` / `--b-city`（或 `--a-lng` / `--b-lng`），脚本自动做经度校正；不给则默认东经 120°（不校正），此时脚本会主动提示"结果可能有偏差"，你要把这句话转达给用户。

**真太阳时有两种口径，默认只做经度校正**：默认校正量是 `(经度 − 120) × 4` 分钟（传统排盘口径）；加 `--eot` 则额外计入**均时差**（±16 分），得到天文学严格意义上的真太阳时。**两者的差别不是小数点级的**——均时差足以把结果推过时辰边界（实测北京全年约 5% 的出生时间会因此换一个时辰，而时辰一换整张盘全变）。默认**不计**，脚本不会静默切换口径。遇到出生钟点紧邻时辰交界的案例，可以用两种口径各排一遍对照，把差异明确告知用户，由对方决定采信哪张。

**真太阳时跨过午夜时，出生日期会跟着改**——这是正确行为，不是 bug。真太阳时是一条连续时间轴，日期与时辰都得取自它；只换时辰、把日期留在钟表轴上，排出的「日 + 时」指向的就不是出生时刻（农历日错一天 → 紫微定位错 → 十二宫全变）。所以输出里的日期**可能与你输入的 `--a-date` 差一天**：西部长经度差城市（喀什、乌鲁木齐、拉萨）的凌晨会回退到前一日，东部（哈尔滨、上海）的深夜会顺延到次日。脚本在出现这种情况时会**显式写明**「真太阳时已跨过午夜，出生日期回退/顺延至 X」——看到这句就把输出里的日期当准，并向用户说明，不要说成排错了。

## 晚子时：子时横跨两日，这是个真陷阱

任一方 `23:00–23:59` 出生时，两种口径排出的是**两张完全不同的盘**（命宫主星、紫微位、格局组全变），不是微调：

| 口径              | 含义                             | 本 CLI                                                     |
| ----------------- | -------------------------------- | ---------------------------------------------------------- |
| **当日早子时**    | 按出生当日的农历日数安星         | 默认。                                                     |
| **晚子时·算次日** | 子时归次日，按次日的农历日数安星 | 该方加 `--a-late-zi` / `--b-late-zi`（或 `--a-branch 12`） |

已验证的等价关系：**`timeIndex 12` ≡ 次日 `timeIndex 0`**（命盘逐宫完全一致）。

脚本行为：

- 任一方给了 `--a-time 23:xx` / `--b-time 23:xx` 时，脚本会提示**该方**的口径问题，并说明当前用的是哪一口径 —— 你**必须**把这段提醒读出来，不能在解读里装作没这回事。
- 逐字读提醒里的两组「紫微落 X · 命宫主星 Y」，据此向用户说明差异有多大，并**建议其确认具体钟点**。
- ⚠️ **该方命盘会整体改变，合盘结论需重跑** —— 晚子时不是只动一方的一个字段，它会推翻已经算出的天作之合判定与夫妻宫断语。别在旧结论上打补丁。
- 若用户确认为 23:00 后出生且要求按传统口径，给该方加 `--a-late-zi` / `--b-late-zi` 重跑，再解读。
- 用了 `--late-zi` 时，输出里的「农历」栏显示的仍是**出生当日**（即真太阳时校正后的日期，可能与 `--date` 差一天；安星则用其次日），两处相差一天是正常的，不要当成 bug。

⚠️ **不要**在没有提示的情况下自行替用户选口径。选错口径的合盘，等于给错两个人算命。

## 工作流

### 第 1 步：排盘取数

```bash
node scripts/purple-star.ts synastry \
  --a-date 1990-05-15 --a-time 09:30 --a-gender male --a-city 北京 \
  --b-date 1993-08-22 --b-time 14:00 --b-gender female --b-city 上海
```

`synastry` 一次给出合盘解读所需的全部结构化数据：双方命宫/夫妻宫/福德宫、天作之合对应关系判定、夫妻宫完整断语、生年四化入夫妻宫、桃花孤克星。

**一次调用即可开始解读，不要分两次跑。**

用户只给农历时：给该方用 `--a-lunar` / `--b-lunar`（闰月加 `--leap`）。只知时辰名时：给该方用 `--a-branch 5`（0-11：0=子 … 11=亥；12=晚子时）。`--time` 与 `--branch` **二选一**。

城市名容错：`杭州` / `杭州市` / `浙江省杭州市` 都能解析；**做了容错解析或存在同名歧义时，脚本会在【出生地解析】里说明**，看到就要留意（歧义会提示候选，让用户确认或改用 `--b-lng`）。

### 第 2 步：按需深入知识源

CLI 已给出双盘数据与断语。需要展开论证时，**直接读这些文件**（它们是本技能的权威依据，不要凭记忆编造）：

| 需要什么                                                 | 读哪里                                              |
| -------------------------------------------------------- | --------------------------------------------------- |
| 十四主星在夫妻宫断语、四化入夫妻宫                       | `scripts/ziwei/synastry-knowledge.ts`               |
| **合盘方法论与评分标准**（五步法、缘分类型、婚期三层法） | `references/synastry-guide.md`                      |
| 四化体系（生年 / 流年 / 流月三层）                       | `scripts/ziwei/sihua.ts`                            |
| 星曜释义（关键词/星性/五行）                             | `scripts/ziwei/constants.ts` 的 `STAR_DESCRIPTIONS` |

**评分标准与完整方法论不在 `synastry` 的输出里**——它们是恒定静态文本（与「这一对是谁」无关，排谁的盘都是同一份），住在 [references/synastry-guide.md](references/synastry-guide.md)，`synastry` 末尾只留一行指针。因此：

- 要在解读里给这段关系**定档（几星）**时，读该文件的「评分标准」节；
- 要展开夫妻宫断语之外的方法论（五步法、缘分类型、婚期三层法）时，读同文件的「合盘分析核心框架」节。

⚠️ 该文件里「四化飞化互参」一类表述是**方法论层面的技法描述**，不是让你去调飞星派的工具——本项目已下线宫干自化与大限四化取宫干（见下文「体系硬约束」）。

### 第 3 步：合参解读

解读合盘时**必须双宫联参**（倪师核心断法）：

> 看婚姻，光看夫妻宫，大错特错，一定要同时看福德宫。

夫妻宫看配偶星性与互动模式，福德宫看感情能否长久。夫妻宫好而福德宫破，"散"。

按这个顺序展开，不要跳步（下方输出契约的四节与这四步一一对应）：

1. **命宫 × 命宫定基调** —— 双方命宫主星互动：性格底色合不合、谁带动谁。
2. **夫妻宫 × 福德宫联参** —— 展开 `synastry` 给出的断语。这是本技能的核心，不能跳过福德宫只论夫妻宫。
3. **四化互动定着力点** —— 双方生年四化互落对方宫位：谁的禄入谁的关键宫（滋养从哪来），谁的忌落何处（摩擦在哪）。
4. **结论落到相处经营的具体行为** —— 不要停在术语堆砌。

### 合盘输出契约

合盘解读与全盘解读共用形态硬约束（直断、虚岁、数据锚定、术语白话、口径转达），结构按此模板——**章节、顺序、命名固定**，`<>` 为待填槽位：

```markdown
## 合盘解读 · <甲方命宫主星> × <乙方命宫主星>

**甲方**：<性别>，<公历日期 钟表时刻>（<城市>）→ 真太阳时 <时辰> · <X>局 · 现行<大限宫>大限（虚岁 <N>）
**乙方**：<同一格式>

**总评**：<2–3 句，先给天作之合判定结论与关键张力点。>

### 命宫 × 命宫

<双方命宫主星互动 2–3 句：性格底色合不合、谁带动谁。>

### 夫妻宫 × 福德宫（双宫联参）

<展开 synastry 输出的断语，3–5 句。夫妻宫看配偶星性与互动模式，福德宫看能否长久——夫妻宫好而福德宫破，"散"。>

### 四化互动

<双方生年四化互落对方宫位，2–4 句：谁的禄入谁的关键宫（滋养从哪来），谁的忌落何处（摩擦在哪）。>

### 综论与建议

<2–4 条，落到相处经营的具体行为。>
```

**形态硬约束**：

- **篇幅**：600–1200 字。
- **表格**：全文 ≤ 2 张，只用在四化互动节；其余内容用短段落与列表。
- **术语**：首次出现配一句白话。每个断语都能指回 CLI 数据（星 / 宫 / 格局名），不凭记忆加星。
- **语气**：直断——先给结论再补依据；不好看的结论也直说，不粉饰。
- **年龄**：一律虚岁，报 CLI 给的数，不换算周岁。
- **口径转达**：CLI 输出里的口径提示（真太阳时校正量、跨午夜改期、晚子时两盘对照、城市歧义候选）出现在基本信息行或紧随其后，**转达完才进入解读**。

## 体系硬约束：三合派，不是飞星派

本项目**严格遵循倪海夏《天纪》三合派**。以下飞星派工具在本项目中已被**主动下线**，你**不得**使用，也不要从代码里把它们捡回来：

- ❌ **宫干自化** —— `algorithm.ts` 已停止填充 `Palace.selfSihua`（注释明确："倪师不主张飞星派宫干自化论"）
- ❌ **大限四化取宫干** —— `algorithm.ts` 已停止生成 `daXians[].siHua` / `stemIndex`
- ❌ **来因宫** —— 飞星派追溯法，不使用

⚠️ **陷阱**：`scripts/ziwei/sihua.ts` **只提供上面那三层四化**（`getSiHuaByStem` / `getYearStemIndex` / `getLiuNianSiHua` / `getLiuYueStemIndex` / `getLiuYueSiHua`）。飞星派的 `detectSelfSihua` / `findIncomingPalaces` / `getDaXianSiHua` 等函数已于 2026-09-27 从该模块**删除**——不是改名、不是移到别处，全仓零调用点。

但 `types.ts` 里的 `Palace.selfSihua` / `DaXian.siHua` 字段与 `SelfSihuaMark` / `DaXianSiHua` 两个类型**仍在**，那是**刻意留下的绊线**：断言盯着它们不被重新填回，字段删了就没东西可盯。**存在不等于该用**——用它们解读就是背叛本项目的体系立场。

可用的是：**生年四化**（出生年干）、**流年四化**（当年年干）、**流月四化**。合盘断语用的是双方**生年四化**互落对方宫位。

倪师核心立场（权威声明见 `scripts/ziwei/sihua.ts` 的「体系基准」节）：

> 大道至简——飞星飞来飞去太复杂，不搞这个。
> 命宫为本，三方为用。
> 人事努力 + 地理调整 > 先天命运（2/3 > 1/3）

## 其他已知事实

- **庙旺利陷口径**：iztro 的 7 级塌缩成 3 级——`bright` = 庙/旺，`dim` = 陷/不，**其余（`得`/`利`/`平`）一律 `normal`**。另注意 `brightness` 字段**只给主星填**：`chart.palaces[].stars[]` 是个**扁平数组**（每项带 `type`，取值为 `major` / `minor` / `sha` / `lucky`，**不存在** iztro 原始的 `minorStars` / `adjectiveStars` 这两个键），只有 `type === "major"` 的那 14 颗带 `brightness`，其余三类不带（信息比 iztro 原始输出少，是口径选择不是缺漏）。
- **年龄一律是虚岁**：`currentAge`（当前年龄）、`daXians[].startAge/endAge`、`palace.daXianAge` 三者**同为虚岁**，以**农历年（正月初一）为界** —— 不是生日，也不是立春。数据来自 iztro 的 `decadal.range`。解读时报给用户的年龄就用这个虚岁，**不要自行换算成周岁**（换算即错，且会连带说错当前大限）。
- **童限**：`currentDaXianIndex === -1` 表示此人**尚未起运**（虚岁小于五行局数，如土五局要 5 岁才起运），此时 CLI 的「当前大限」显示 `—`。这是正常的，不是数据缺失——此时按命宫论，不要硬套一个大限。合盘里任一方未起运时，「现行大限」栏会缺一边，照实转达。
- **十二宫顺序**：`chart.palaces` 按**地支数组序**排，实测为 `2,3,…,11,0,1`（**寅起**）——既不是 0-11（子起），也不是宫位顺序（命宫起）。定位某宫请按 `branch` 建索引，**不要依赖数组下标**。
- **知识来源分级**：`synastry-knowledge.ts` 与 `references/synastry-guide.md` 里「倪师说」引号句部分为传统口诀的**风格化转述**，不一定是《天纪》逐字原话，引用下断语须注明口径。

| ---------- | ------------------------------------------------------------ |
| `synastry` | **主力命令**。双人合盘：双宫联参 + 夫妻宫断语 + 四化入夫妻宫 |
| `selftest` | 回归自检（末行自报项数）。改动本技能后跑一次                 |

**合盘参数**：`a-` / `b-` 前缀 + 单人参数——`--a-date` / `--a-lunar`（+`--leap`）/ `--a-time` 或 `--a-branch 0-12`、`--a-late-zi`、`--a-eot`、`--a-gender`（**必填**）、`--a-lng` / `--a-city` / `--a-province`、`--a-name`。**双方各给一份。**

**输出选项**：`--json`（唯一不带前缀的旗标）。

> ⚠️ **无前缀的出生信息旗标既不生效也不报错**（见上文「铁律」的警告）。`--a-` / `--b-` 前缀**用在别的命令上会报错**，反方向却不会——所以漏前缀只能靠你自己复核。`--a-date` 写成 `--date`、`--a-city` 写成 `--city`，脚本照常跑完，排出的是默认值的盘。

完整帮助：`node scripts/purple-star.ts help`

## 若脚本报错

遇到报错、或想确认当前跑的是哪一份内核 —— 读 [references/troubleshooting.md](references/troubleshooting.md)（启动期报错、参数报错、改完本 skill 后的回归方式都在那里）。

⚠️ 但**最要紧的一条留在这里**，因为它不会报错：无前缀的出生信息旗标在 `synastry` 上被静默忽略（见上文「铁律」）。自查方法是看输出里的「真太阳时校正」栏 —— **校正量为 `+0 分` 而用户明明给了出生地，就是漏了 `a-` / `b-` 前缀**，补上重跑，别拿这张盘解读。
