# 排障：合盘 skill 脚本报错对照表

本文件是 `SKILL.md` 的延伸——**遇到报错或异常输出时才读**，正常解读流程用不到。

⚠️ 本技能**不排盘**，所以这里**没有**「未收录城市」「缺少性别」这类出生信息报错——那些发生在第一步（`purplestar-astrology`），报错也由那边给。本技能能报的错只有两类：**命盘 JSON 不合格**（占绝大多数）与**参数用错**。

## 命盘 JSON 不合格（本技能最常见的报错）

这类报错的**根因通常不在本技能身上**，而在第一步用错了命令。见到就先回去复核那两条排盘命令。

| 报错（片段）                                             | 原因与处理                                                                                                                                                          |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `缺少 --a-chart / --b-chart：本 skill 不排盘……`          | 两方命盘必须各给一份，本技能没有出生信息可回退。按报错里的指引先在 `purplestar-astrology` 里排盘。                                                                  |
| `读不到甲方命盘文件：<路径>`                             | 路径写错，或排盘那一步根本没跑成（重定向建了空文件 / 文件在别的机器上）。先用 `ls` 确认文件在，且**非空**。                                                         |
| `<甲方>命盘文件不是合法 JSON`                            | 重定向拿到的不是 JSON。**最常见的原因**：排盘命令失败了，写进文件的是那行错误信息。打开文件看一眼就知道。                                                           |
| `命盘文件里没有命盘对象（顶层键 \`chart\`）`             | **拿 `chart --json` 顶替了 `analyze --json`**。两份都输出 JSON，但 `chart` 的**顶层就是命盘本身**，没有 `chart` 键，也没有四化落宫与排盘依据。改用 `analyze` 重排。 |
| `缺 \`nativeSiHua.located\`（生年四化落宫）`             | 同上，或那份 JSON 被别的工具裁剪过。「四化入夫妻宫」一节依赖它，缺了会静默少一节结论，故此处拦下。                                                                  |
| `缺 \`lateZi\`（晚子时标记）`/`缺 \`basis\`（排盘依据）` | 同上。这两个字段只有 `analyze --json` 有；缺了就无法转达真太阳时与晚子时提示。                                                                                      |
| `命盘里找不到「夫妻宫」宫`                               | 那份 JSON 的宫名口径不对（不是本项目排的盘）。报错里会列出该盘实际的十二宫名，据此判断来源。                                                                        |
| `命盘异常：<某方命宫>（地支 X）不在十二宫内`             | 命盘对象损坏（十二宫不齐）。重新排一张。                                                                                                                            |

## 参数报错

| 报错（片段）                                                                                 | 原因与处理                                                                                                                   |
| -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `未知参数 --date。`                                                                          | **本技能不认出生信息旗标**（不排盘的 skill，作用域里就没有它们）。日期 / 时间 / 性别 / 出生地都属于 `purplestar-astrology`。 |
| `未知参数 --cahrt。最接近的是 --chart。`                                                     | 旗标拼错。本技能只认 `--chart` 与 `--json`；带前缀时写成 `--a-chart` / `--b-chart`。                                         |
| ``--a-chart：`a-` 前缀只有 synastry 命令认（它要分别读 a- / b- 两方）。当前命令是 selftest`` | 把前缀旗标给了一个不收前缀的命令。`selftest` 只做回归自检，改用 `--chart`。                                                  |

## 启动期报错

| 报错                                                     | 原因与处理                                                                                                                                                                                   |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Cannot find module '.../scripts/synastry-knowledge.ts'` | skill 目录不完整。⚠️ 缺的若是 **`synastry-knowledge.ts`**（合盘断语库），这个 skill 就没有存在意义；缺别的文件则是拷贝时漏带。从本仓库（或本 skill 的发布包）补回 `scripts/` 下缺的那份即可。 |
| `Unknown file extension ".ts"` 或 TS 语法报错            | Node 版本过低，需 ≥ 22.15（本技能靠**原生类型擦除**直接加载 `.ts`，不注册解析钩子）。                                                                                                        |

⚠️ 这里**不会**出现 `Cannot find module 'iztro'`，也不会出现 `Cannot find module 'cac'` —— 本技能已无排盘依赖，参数解析是自带的几十行循环，`package.json` 里**一条依赖都没有**，连 `npm install` 都不需要。若真见到这两个报错之一，说明跑的不是本 skill 的脚本。

## 确认跑的是哪一份内核

只有一份 —— **`scripts/` 就是本技能的内核**（`purple-star.ts` 用 `import.meta.url` 定位，不依赖 cwd，也没有任何环境变量可覆盖它）。

`selftest` 输出的**第二行**（形如 `内核根：<路径>`）就是当前生效的那一份，交付解读前据此核对。

## 改完本 skill 之后

```bash
node scripts/purple-star.ts selftest   # 命令冒烟 / 命盘护栏 / 参数面 / 参考文档与知识源 / SKILL.md 一致性
```

⚠️ **本 skill 的每个文件都是它自己的实现，就地改即可，没有「改源再同步」这回事**（2026-09-27 起与 `purplestar-astrology` 不再有派生关系）。`scripts/` 下的五个文件各管一段：

| 文件                    | 管什么                                                      |
| ----------------------- | ----------------------------------------------------------- |
| `purple-star.ts`        | 入口：参数面（声明表 + 解析循环 + 最近邻建议）+ help + 分发 |
| `commands.ts`           | 命令表 + `synastry` 的渲染                                  |
| `chart-view.ts`         | 读 `analyze --json` 并校验；**本 skill 的类型契约**在这里   |
| `selftest.ts`           | 回归自检                                                    |
| `synastry-knowledge.ts` | 合盘断语库（纯数据）                                        |

⚠️ **`npm test` 不在本 skill 内** —— 它是仓库级的。而**引文核对**（那些「倪师说」引文有没有未核实却强归属的）也**不在本 skill 的 `selftest` 里**：它住在仓库的 `test/citations.test.ts`，扫描范围是**全部三个 skill**。改完 `synastry-knowledge.ts` 的引文后，回仓库跑 `npm test`（只拷走了本 skill 的用户跑不了那条，那是刻意的——守卫的受众是改内核的开发者）。
