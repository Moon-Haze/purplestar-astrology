# Proposal

## Why

`openspec validate --all` 有两条既有警告：extensibility「内核与内容严格分层（ADR-003）」与
quality-gates「分析数据表键域互证」的 requirement 描述超 500 字符（实测 594 / 581），来自
前次归档折回的长文本。AGENTS.md 的口径是「改完 specs 跑 validate --all，须全部通过、零警告」，
这两条警告让每次验收都带着已知红点，新警告混在里面不再显眼。本次把两条描述裁到 500 以内，
冗余细节由已覆盖同一形态的场景承载，规范语义不变。

## What Changes

- MODIFIED `extensibility`「内核与内容严格分层（ADR-003）」：描述 594 → 485 字符（delta 实测）；
  删去与「断言组豁免边界」场景重复的守卫红形态枚举（多边 / 少边 / 白名单文件消失），删去
  「内核只暴露纯函数供插件消费」（「插件反向依赖」场景 THEN 承载），SHALL 义务、豁免白名单
  枚举与全部 3 个场景原样保留
- MODIFIED `quality-gates`「分析数据表键域互证」：描述 581 → 460 字符（delta 实测）；删去
  与场景重复的三处细节（按星稀疏豁免 →「格局补注键漂移」、空数组退化禁令 →「断言空退化」、
  可选链缩水禁令 →「全域表缺宫」），SHALL 义务、域清单与全部 7 个场景原样保留
- 纯文本重组：义务集合、场景集合、判定形态（断言 / 反向注入）零变化

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `extensibility`: 「内核与内容严格分层（ADR-003）」描述去冗余，场景不动
- `quality-gates`: 「分析数据表键域互证」描述去冗余，场景不动

## Impact

- 规范面：两个主 spec 的 requirement 描述文本；**不触代码与内核**，属**内容扩展档**（不重跑
  内核回归），验收为 `openspec validate --all` 全部通过、零警告
- 由上一变更（polish-prose-with-humanizer）的留档事项派生；完成后零警告口径恢复可执行

## 不做什么

- **不拆 requirement**：两条描述都是单一行为（分层、互证）的冗长表述，不是多行为混合。拆分
  会把豁免 carve-out 与其所属规则分开，读者要在两处拼回完整口径；且 MODIFIED 块不得丢场景，
  迁移场景另需 ADDED 承接，结构收益为零
- **不动场景**：全部场景逐字保留，语义与判定形态不变
- **不动 validate 阈值**：500 字符是 CLI 内建口径，不在本变更面内

## 被否决的备选方案

1. **拆成两条 requirement**：见「不做什么」第一条；规则与它的例外分家，结构收益为零
2. **忽略警告或等下次顺手改**：零警告口径每多带一条已知红点就稀释一分；裁剪本身极小，
   专门开 change 的成本低于口径长期失守
