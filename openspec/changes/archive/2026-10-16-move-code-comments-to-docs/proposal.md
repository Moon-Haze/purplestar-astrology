# Proposal

## Why

`scripts/` 内核树的注释密度已到了淹没实现的程度：122 个 `.ts` 共 100,829 行，其中 28 个文件的注释行占比超过 50%（`palace-relations.ts` 81%、`types.ts` 73%、`patterns/index.ts` 79%）。这些长注释多为**模块设计论证**（为什么存在、历史包袱、与其他模块的契约）与 **⚠️ 防呆警告**（哪里不能改、改了会怎么静默出错），它们是有价值的知识，但当前位置让「读实现」变成「在注释里淘金」。

把长篇论证搬进 `docs/code/`（仓库协作者向，按模块单元聚合），代码里只留一行摘要 + 指路牌，实现部分的可读性即可恢复，而知识一条不丢。

## What Changes

- **新建 `docs/code/`**：约 15 篇文档，按「协作者改代码时会打开的单元」聚合 122 个源文件（引导层 / 排盘内核 / 格局 / 论断 / 数据 / 语料 / 知识源 / 流派 / 合盘 / CLI 各层），另加一篇 `README.md`（导航 + 维护纪律）。
- **注释四分类处置**（边界经与用户确认）：
  - A 类 TSDoc 契约（`@param` / `@returns` / `@throws`）——**留**（短、IDE 悬停值千金）。
  - D 类口径锁（解释不直观算式/显式配置的一行注释）——**留**。
  - B 类模块头论文（`@packageDocumentation` 长文）——**搬**，代码留一行摘要 + 指路牌。
  - C 类 ⚠️ 防呆警告（remarks/行内「不要改这里」）——**搬**，代码留 ⚠️ 结论一行 + 指路牌。
- **两处仓库级联动**：`CLAUDE.md` 中「先读 `types.ts` 里紧挨着它们的说明」改为指向 `docs/code/` 对应文档；`docs/README.md` 目录表登记 `docs/code/`。
- **引文守卫不动**：搬迁内容为零违例（刚从零违例树上搬下），`docs/` 非 `.ts` 不在守卫扫描范围；在 `docs/code/README.md` 记软纪律（搬入文档的倪师引文与源码同受核对表约束）。将来硬化守卫支持 `.md` 另案提案。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

无。本变更为纯注释搬迁：CLI 行为、输出契约、扩展点、验证纪律均不变，无 spec 级行为变化（`skip_specs: true`）。

## Impact

- **源码**：`scripts/` 下 28+ 个高注释密度文件瘦身，**不动任何可执行代码**（不改签名、不改逻辑、不改字符串文案——已核实无测试断言源码注释文本，引文守卫只匹配引文模式）。
- **文档**：新增 `docs/code/`（约 15 篇 + README）；修改 `CLAUDE.md`（1 处引用）、`docs/README.md`（目录表 1 行）。
- **测试**：零改动。`typecheck` / `selftest` / `npm test` 三重闸门行为不变，作为每批搬迁的防手滑验证。
- **分发**：零影响。`docs/` 本就不进 zip；`scripts/` 的可执行部分逐字节不变。

### 不做什么（Non-Goals）

- 不改任何可执行代码、类型标注、错误文案。
- 不动 A/D 类注释，不动 `SKILL.md` / `references/`（分发件内容不变）。
- 不扩展引文守卫扫描 `.md`，不改任何测试基础设施。
- 不新增 `test/*.test.ts`（无新行为需要断言）。
