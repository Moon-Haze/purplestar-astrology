# Design

## Context

见 proposal.md（Why / What Changes）。补充只有读代码才知道的现状与约束：

- **注释存量**：`scripts/` 122 个 `.ts` 共 100,829 行、6,114 注释行；28 个文件注释占比 >50%。注释分四类：A = TSDoc 契约（`@param`/`@returns`/`@throws`），B = 模块头论文（`@packageDocumentation` 长文），C = ⚠️ 防呆警告（「不要改这里」），D = 口径锁（解释不直观算式的一行注释）。
- **已核实的约束**：无任何测试断言源码注释文本（测试的 `readFileSync` 只指向 `SKILL.md`/`test/README.md`/fixtures/缓存）；引文守卫读 `scripts/` 全文但只匹配「倪师…说：引文」模式，`.ts` 之外不扫；全仓唯一指向代码注释的跨文件引用是 `CLAUDE.md:211`。
- **分发形态**：`docs/` 不进 zip，是仓库协作者向目录；`scripts/` 的可执行部分逐字节不变。

## Goals / Non-Goals

**Goals:**

- 实现区可读性恢复：搬迁后源码文件能「一眼扫完实现」，长篇论证不再插在签名之间。
- 知识零丢失：每条 B/C 注释原文进入 `docs/code/`，可检索、可链接、可整篇审阅。
- 防呆效力维持：搬走的每条警告在代码里留 ⚠️ 结论 + 指路牌，改到该处的人被迫看到。
- 行为零变化：可执行代码（签名、逻辑、字符串文案）逐字节不变。

**Non-Goals:**

- **不做改写润色**：搬迁是搬运，注释原文进文档——「文档一份、注释一份」的措辞分叉从起点就不允许发生。
- 不建文档生成工具链（本仓无构建步骤，不为此破例）。
- 不强推「文档与源码逐行对应」的机器校验（将来如做，属验证纪律变更，另案）。

## Decisions

### D1：按「单元」聚合 15 篇，而非一文件一篇

聚合粒度 = 协作者改代码时会一次性打开的单元：引导层 / 排盘内核 / 格局 / 论断 / 数据 / 语料 / 知识源 / 流派 / 合盘 / CLI 五层。
**Why**：122 篇的导航成本比现状更糟；按 ADR 分篇又太粗（一个 ADR 横跨多个目录，改一个函数要猜去哪篇）。
**Alternatives**：一文件一篇（导航灾难）；按分层红线 ADR-003 两篇（过粗，丢失「哪层」的定位感）。

### D2：指路牌 = 一行摘要 + ⚠️ 结论 + 仓库根相对路径

```ts
/**
 * 宫位地支关系单点：对宫 / 三方四正 / 按地支取宫。
 * ⚠️ test/ 里两处内联重算是刻意的独立预言机，判据与历史见
 *    docs/code/chart-kernel.md。
 */
```
路径口径为**相对仓库根**（与 `CLAUDE.md` 的路径约定一致，不写相对源文件的 `../..`）。
**Why**：摘要行保住「这模块是什么」的最小悬停上下文；⚠️ 行保住结论——读者不必点进文档就知道「这里有雷」；路径用仓库根口径让 `CLAUDE.md`、Issue、PR 描述里抄录时不会错。
**Alternatives**：只留路径（悬停变废纸）；留摘要不留 ⚠️（防呆效力打对折）。

### D3：A/D 留、B/C 搬（判据记录）

判据是「消费者的可达场景」：TSDoc 契约的消费者是 IDE 悬停里的**调用方**（写调用代码时才需要），必须就地；设计论证的消费者是**要改这个模块的人**，`docs/` 可达且更适合整篇读。口径锁（D）是「防将来人删掉显式配置」的钓鱼线，一行成本，留。
**Alternatives**：全搬（悬停废）；全留（现状，无改善）。

### D4：引文守卫不扩展，软纪律入 `docs/code/README.md`

搬迁内容零违例（刚从零违例树上搬下）；守卫的 `collectTsFiles` 只收 `.ts`，扩展扫 `.md` 是改动验证基础设施（按仓库规矩单独提案），且 docs 里的合法古籍引用会误报。
**How**：`docs/code/README.md` 写明「搬入本文档的倪师引文与源码同受核对表约束」——软约束，将来硬化另案。

### D5：分批按 15 单元，内核先行，每批三重闸门

顺序：`chart-kernel`（内核契约，防呆密度最高，顺带验证指路牌模式）→ CLI 五层 → 知识/扩展层（patterns / analysis / corpus / knowledge / school / synastry / data-tables）→ `boot-layer` 收尾。
**Why**：内核的冻结契约与绊线最多，最先搬完才能让其余篇有「模式样板」可抄；boot-layer 最后搬（它的注释被最多搬迁引用当范例）。
每批判据：`git diff` 只含注释行与新增文档；`node scripts/purple-star.ts selftest` 全绿 + `npm test` 全绿。收尾全量 `npm run typecheck` + `lint` + `format`。

## Risks / Trade-offs

- [未来协作者只看代码不读 docs，⚠️ 失效] → 指路牌强制「改到这行必看见」；验收判据：每个被搬空的文件残留注释含 ⚠️ 与 `docs/code/` 字样。残余风险承认存在：指路牌是概率防御，不是机制防御。
- [文档漂移：模块演进后 `docs/code/` 论述过时] → README 维护纪律（改模块设计先改文档）。此风险现状同样存在（注释贴着代码反而更难整体审阅），搬迁不使其恶化。
- [搬迁手滑碰了可执行代码] → 每批 `git diff` 审阅 + 三重闸门；只允许注释行 diff。
- [skill 宿主在 `~/.claude/skills/` 内读 `scripts/` 时看不到 `docs/code/`] → 可接受：宿主的规范来源是 `SKILL.md` + `references/`，注释从来不是它的契约面。
- [TSDoc `{@link}` / `@packageDocumentation` 在 md 中无对应物] → 文档内改用相对路径链接；代码侧保留的 A 类 TSDoc 不受影响。

## Migration Plan

无运行时部署概念；「迁移」= 15 批搬迁。每批四步：写 `docs/code/<unit>.md`（原文照搬 + 单元导航）→ 瘦身源码注释（留指路牌）→ `selftest` + `npm test` → `git diff` 审阅（只动注释行）。回滚 = 单批 `git revert`。收尾批：`CLAUDE.md:211` 联动改指向、`docs/README.md` 登记 `docs/code/`、全量 typecheck/lint/format。无文件物理位置变动，import 语句、`load<>("@/…")` 字面量、`resolve(ctx.root, …)` 三类字符串零涉及。

## Open Questions

无。分类边界（A/D 留、B/C 搬）、粒度、守卫处置、分批顺序均已在此确认。
