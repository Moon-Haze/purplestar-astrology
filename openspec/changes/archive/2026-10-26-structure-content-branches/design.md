# Design

## Context

`StarContent`（`analysis/data.ts`）以「星 × 13 语境键」组织语料，语境值为 `string | GenderField`（性别投影由 `selectGender` 单点完成，2026-10-24 落地）。四化与亮度条件句目前内嵌在语境散文里，无结构标记；消费点两处——`overview-material.ts` 的 `content`（本宫核心论断）与 `views/surround.ts` 的 `fullContent`（三方四正联动复引）。判定信号现成：星的 `mutagen`（`"禄"|"权"|"科"|"忌"|""`）与 `brightness`（`bright|normal|dim`）。

## Goals / Non-Goals

**Goals:**

- 条件分支结构化 + 投影：交付文本只含命中分支，分支文本逐字保留。
- 渲染层双形态兼容，语料分批迁移，迁移进度机器可查。

**Non-Goals:**

- 自由条件句（逢火铃、煞星会照等）结构化——无现成单字段判定信号，强行判定会把命理逻辑塞进投影层。
- 措辞修订、内容增删（只动承载结构，不动内容本身）。
- `--report` 跨板块去重（`refine-report-dedup-citations` 域）。

## 不可逾越的约束

- **分支文本逐字保留**：投影后的命中分支必须与原散文子句逐字节一致——内容不变是本 change 的验收底线。
- **引文纪律**：迁移拆句不得新增「倪师 / 倪海厦 + 引号句」形态；撞上即在 `analysis/grades.ts` 登记，否则引文守卫变红。
- **`selectGender` 单点不被绕开**：性别投影仍是唯一性别机制，分支投影与其组合而非重复实现（避免两套投影漂移）。
- **分层红线**：`data.ts` 是知识内容层，投影改动不得反向依赖 `cli/`；排盘内核零接触。

## Decisions

### D1 分支承载为语境值的第三种形态，不建平行表

语境值类型从 `string | GenderField` 扩展为 `string | GenderField | BranchedContent`，`BranchedContent = { common: string | GenderField; sihua?: { lu? quan? ke? ji? }; brightness?: { bright? dim? } }`，`common` 保留无分支散文、各分支键收对应子句。

- **备选 a**：渲染时正则切「化X则」——**否决**：句式有变体（「化禄则」/「化忌时要防」），正则切分不可靠，这正是要消灭的「无结构标记」本身。
- **备选 b**：原文不动、另建星 × 宫分支句平行表——**否决**：平行表与原文必漂移（`wenmo-brightness` 的 JSON 版教训：手抄副本必丢内容，靠维度对拍兜底不如单一承载）。
- **两面**：收益——类型校验逼出全部消费点（typecheck 即接缝验证）、单点承载无副本；代价——语境值类型联合变宽，消费点全部要收窄类型（一次性成本，恰好是接缝判据的验证过程）。

### D2 分支投影与性别投影组合为单一投影入口

新增 `selectBranches`（按星实际 mutagen / brightness 选分支），与 `selectGender` 组合成一个投影函数供消费点调用；内部次序为**先结构后性别**（分支字段内可含 `GenderField`，逐层剥）。

- **备选**：消费点各自组合两函数——**否决**：两个消费点（overview-material / surround）日后必漂移（`buildOverviewMaterial` 收单点的历史正是为此）。
- **两面**：收益——消费点单一、投影语义一处说清；代价——投影函数复合，断言要能区分「分支选错」与「性别选错」两种失败。

### D3 分批迁移，批次按报告曝光度排

首批迁 `--report` 实测全枚举最重的条目（武曲 · 财帛、太阳 · 子女、太阴 · 子女、廉贞 · 官禄、贪狼 · 夫妻、天同 · 疾厄等）；后续批次扫剩余条目。每批独立验证：命中 / 未命中断言 + 未迁移条目 diff=0。

- **备选**：一次全量迁移——**否决**：182 组合一次改动无法逐块审查，且部分条目是自由散文无标准句式，强行结构化必然改措辞（违反逐字保留底线）。
- **两面**：收益——每批可验证、可回滚；代价——双形态兼容期拉长，需要 D4 的收敛守卫防止「永远在迁移中」。

### D4 残留句式扫描作为迁移收敛守卫

`test/invariants.test.ts` 增不变式：已迁移条目 `common` 散文中不得残留「化X则 / 化忌时」「入庙则 / 落陷则」句式；刻意不迁移的自由条件句进**显式豁免清单**（文件内常量，条目可数）。

- **两面**：收益——迁移进度与回滑机器可查，豁免显式化避免「散落的应该」；代价——清单需要维护，但它把隐式决策变成了显式决策（与「跳过必须看得见」同一纪律）。

## Risks / Trade-offs

- [拆句触发引文守卫] → 每批迁移跑 `test/citations.test.ts`；迁移只动承载结构、不新增引语，守卫变红即说明误动了措辞，按红灯回查。
- [联合类型扩散导致消费点大面积红] → 这是特性不是缺陷：typecheck 逼出全部消费点逐一收窄，漏改无处遁形。
- [未命中分支消失被误读为「文案丢了」] → spec 已钉「命中逐字保留 + 未迁移 diff=0」双向断言；交付说明里写明这是内容行为变化的目的本身。

## Migration Plan

分批落地，每批自足验证（结构化 → 断言 → diff=0 → selftest）；全部批次完成后豁免清单收敛、残留扫描归零。回滚 = revert 对应批次 commit，批次间无耦合。
