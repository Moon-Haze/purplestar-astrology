# Design

## Context

`README.md` 现为 AI/维护者视角（见 proposal 的 Why）。仓库根 = skill 根的形态不变，
README 在分发件外（`distribution` spec：不进包），改写无行为面。语料授权与用字决策
已有既定事实：天纪语料 CC BY-NC-SA；「倪海厦」用字保留并须带来源与免责
（skill-audit 2026-10-13 §九）；**代码侧许可未声明**（package.json / SKILL.md 均无
license 字段）。

## Goals / Non-Goals

**Goals:**

- 访客 30 秒内能回答：这是什么、能干什么、怎么装、怎么用；
- 全部既有分发硬承诺在改写后仍可逐项找到；
- 维护者内容有明确去处，不丢失。

**Non-Goals:**

- 不替仓库发明代码许可（现状未声明，README 不新增声明）；
- 不写分发件内部的技能使用教程（那是 `SKILL.md` / `references/` 的职责）。

## Decisions

1. **章节序（门面结构）**：标题与一句话定位 → 能做什么（三域清单）→ 输出示例 →
   快速开始（装进 AI 助手 / 仓库内直接用 CLI 两条路）→ 命令速览 → 仓库地图
   （顶层目录一句话表）→ 体系口径（收敛为短节）→ 来源与授权 → 给开发者
   （验证三件套 + 指路 `AGENTS.md` / `docs/`）。替代方案「保留现结构微调」弃——
   问题正是结构性的（视角错位），微调救不回第一屏。

2. **示例的选取与红线**：排盘示例用仓库文档同款虚构出生信息
   （`2011-06-24 07:45 男 杭州`），apply 时实跑 `astrology` 取真实输出节选
   （基本信息面板 + 运限速览数行即止，不贴整屏）；另给一行 `knowledge --search`
   示例。引文红线：选段避开「倪师 / 倪海厦 + 引号句」形态——README 在引文守卫
   `.md` 扫描面内（`test/lib/citation-guard.ts` 的 `scanMarkdownCitations`），
   引入未登记引文会 `npm test` 变红；本变更不新增 `grades.ts` 登记。

3. **维护者内容的下沉去处（不新开文件、不复制）**：
   - 「数据来源」代码模块地图 → `docs/code/` 已有同面地图，README 留一句指路；
   - 「`scripts/` 不拍平」的数百处 import 警告、「字节可复现」的 zlib 实现细节、
     `pickRoot` 机制 → `AGENTS.md` 与 `docs/` 已有，README 各留**一句承诺**
     （「多层子目录原样收包，勿拍平」「同源码多次构建 sha256 相同」）不展开。

4. **计数不写死（config「计数不写死」红线在文档面的应用）**：删「160/160」
   「131 条目」「约 1.2 MB」等会随代码漂移的数字，改定性（「selftest 应全绿」
   「条目数以实打为准」）。`⏭` 跳过机制等运维细节同理下沉。

5. **快速开始分两条路**：(a) 装进 AI 助手（解压 zip 或只拷 4 项 → `npm install`
   → selftest）——保留「不 `cp -r` 整仓」与 641 MB 坑警告；(b) 仓库内直接用 CLI
   （`node scripts/purple-star.ts astrology …`，开发者/尝鲜视角）。安装节是现文
   最健康的部分，承诺原文基本保留、仅重排。

## Risks / Trade-offs

- [示例输出随版本漂移（贴出的节选与实跑不一致] → 节选控制在面板/速览等低频变动
  区块，且 apply 时以当日实跑为准；接受轻微滞后，不写死断言数。
- [下沉内容被误删而非下沉] → tasks 逐项列「下沉清单」，apply 时对每项确认去处
  （`docs/code/` / `AGENTS.md`）已有承接，README 保留指路句。
- [改写引入引文守卫红灯] → 决策 2 的红线 + tasks 的验证步（跑引文守卫）双保险。

## Migration Plan

单文件重写，`git diff` 可整体审阅；不满意直接 revert 单文件，无迁移步骤。
