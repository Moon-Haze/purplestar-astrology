# Design

## Context

`getTopicReport`（`scripts/analysis/report.ts`）同时服务两个场景：`--topic` 单主题查询（词典用途）与 `--report` 的 13 板块装配（交付物用途）。「当前大限」由 `renderDecadal(ctx)` 渲染，其输出只依赖 `chart.currentDx`、与 topic 无关，13 个板块因此逐字相同；「三方四正联动」由 `renderSanFang(ctx)` 对三方宫主星输出 `fullContent` 全文，十三宫互为三方导致同一全文跨板块复现 4–5 次。经典出处由 `buildReport`（`scripts/cli/commands/report.ts`）的 `topicCitations` 检索：宫位专章（书内章节标题含宫名，仅覆盖命 / 财帛 / 官禄 / 夫妻四宫）优先，其余走 `p.text.includes(star)` 纯子串全局检索。装配层 `buildReport` 本就是文档级事务（板块序、文档头、尾注）的归属层。

## Goals / Non-Goals

**Goals:**

- `--report` 场景：大限节 13 → 1；论断全文首现原则；引文语境过滤。
- `--topic` 场景：输出与改前基线逐字节一致（零变化）。

**Non-Goals:**

- 语料文本的全分支结构化（change `structure-content-branches` 承接）。
- 13 板块顺序、文档头字段、尾注内容（产品口径，不动）。
- 排盘内核任何模块（见 proposal「不做什么」）。

## 不可逾越的约束

- **分层红线（ADR-003）**：装配层改动不得反向依赖内核状态修改，`analysis/` 与 `corpus/` 不得反向依赖 `cli/`——去重状态由 `cli/commands/report.ts` 持有、经 `ReportOptions` 正向递入。
- **冻结内核契约**：`test/kernel-contract.test.ts` 盯排盘内核导出，本 change 不触；`getTopicReport` 不在冻结面内，但其签名扩展须同步 `analysis/index.ts` 门面。
- **体系立场**：不引入飞星派任何口径；引文只出自本仓古籍库、不改写拼接（「经典出处是事实层」）。
- **轻路径纪律**：`report-assembly` 新 capability 的行为全部落在 CLI 装配路径，不得因此让 help / 未知命令路径触发重语料加载。

## Decisions

### D1 去重状态由装配层持有，经 options 正向递入内核

`ReportOptions` 增加可选的装配状态（已见全文集合与首现板块映射），`buildReport` 按 13 板块顺序逐节传递；`renderSanFang` 输出全文前查集合——未见给全文并登记，已见输出「徽标 + 指引行」。

- **备选 a**：内核 `getTopicReport` 自行感知报告全局——**否决**：单主题语义的内核不该知道「我是报告的第几节」，职责越界且 `--topic` 路径被迫承担分支。
- **备选 b**：装配层对成品 Markdown 做后处理正则删节——**否决**：对生成文本做正则手术脆弱（段落边界靠文本特征猜），且指引行需要「首现在哪个板块」的结构信息，后处理已丢失。
- **两面**：收益——`--topic` 默认路径零改动（options 缺省即现状）、装配层是文档级事务的既有归属（deletion test：删掉这层状态，去重逻辑就得散进内核各 view，是复杂度搬家不是消解）；代价——`ReportOptions` 公开面扩展，`analysis/index.ts` 门面与下游测试同步。

### D2 大限节抽出为文档级独立节，置于口径提示之后、首板块之前

13 个板块内的「当前大限」小节整体移除，改为文档头区的独立小节（归属「全盘」而非任一主题）。

- **备选**：保留首板块（命格总览）内、其余删除——**否决**：大限不属于「命格总览」主题，塞入会让首板块意外膨胀；独立节在 `references/output-contract.md` 的报告结构描述中也更好表述（「文档头区含大限一览」vs「首板块内多一小节」）。
- **两面**：收益——13 → 1、位置显眼、与「运限速览」的概览语义对齐；代价——报告顶层结构多一个非主题小节，`output-contract.md` 与相关断言同步（一次性成本）。

### D3 引文相关性过滤：主题星判定与语境词共现双通道

全局检索候选段落满足其一即收录：① **主题星判定**——主星名在段落中出现 ≥2 次（段落以论述该星为主）；② **语境词共现**——段落含主星名且含该宫语境词（宫名核心 / 十二宫主管领域词的古文用语，收为数据表、按宫名键、单一角色）。专章命中免滤（标题含宫名即语境自证）。

- **为什么是双通道而非单词表**：实现期以样例盘基线预演单词表方案，12/13 板块的「经典出处」整节省略——古籍星曜论段落（「七杀为将星……七杀守命……」）是该星在任何宫的权威出处，天然不含宫名，单词表把弱关联误杀成零引文。错关联的真实特征是「该星仅被罗列」（机月同梁格句含「天同」、巨门论句尾带「太阳」——星名恰出现 1 次），「主题星判定」恰好挡住这类；两通道并集覆盖「论星段」与「论宫段」，罗列段两边都不满足。
- **备选 a**：接 `annotations` 引文核对表做白名单——**否决**：核对表的职责是引文准确性核对，挪来做相关性过滤是常量身兼两职（`TOPIC_KEYS` 一名两用教训）。
- **备选 b**：模型侧过滤——**否决**：CLI 产物必须确定性，宁可启动失败也不产出不可复现的装配结果。
- **两面**：收益——确定性、零新依赖、错关联（评估阶段实测的健康节机月同梁格挂靠）全挡、星曜论出处保留；代价——「星名 ≥2 次」是启发式，主题星只出现 1 次的短论段会被误杀；对策是宁缺勿滥（省略优于错挂）+ 反向注入断言先行，误杀案例出现时再调阈值（判据参数是常量，调整不动结构）。

### D4 去重键 = 论断全文文本本身

已见集合以全文文本（串本身或其摘要指纹）为键，首现原则按字面执行：同一段文本只给一次全文。

- **备选**：按（星名，宫名）键——**否决**：同星同宫文本在未来语料调整后可能出现变体，按文本键不需要追踪「哪对键对应哪段文」，少一层映射维护（抽象 justify：删掉键映射层，直接 Set 判重，少写一个结构）。

## Risks / Trade-offs

- [生成物大 diff：`docs/cli-samples.md` 与 `tools/samples/` 随去重重导，diff 行数大] → 先取基线再动手，重导后逐块核对 diff 只含预期变化（大限 13→1、复现全文降级、引文删减），不夹带排版噪声。
- [--topic 与 --report 行为分叉引入回归] → 单主题基线逐字节 diff=0 断言钉住（spec scenario 已列）；selftest 参数面契约组同步。
- [语境词表误杀真相关引文] → 双通道判据（主题星 ≥2 次或语境词共现）兜住星曜论段落；宁缺勿滥 + 专章免滤 + 反向注入断言先行；上线后若发现某宫系统性缺引文，再调词表或阈值（词表与阈值是数据不是逻辑，增补不动代码结构）。
- [`ReportOptions` 扩展的公开面涟漪] → options 缺省值保持现状行为，`--topic` 与合盘等既有调用点无需改动即回归原行为。

## Migration Plan

一次性切换（CLI 无跨版本消费承诺）：实现 → 单主题基线 diff=0 验证 → 生成物重导 → `typecheck` + `selftest` 全绿 → 交付。回滚 = revert 单 commit。
