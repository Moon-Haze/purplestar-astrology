# Design

## Context

`TOPIC_SUGGESTIONS`（`analysis/data.ts`）是 13 主题 × 3 条的静态文案表，被 `getTopicReport`（`analysis/report.ts`，注释言明「继续深度追问」是交互尾巴、报告不带）同时用于 `--topic` 终端输出与 `--report` 板块小节。建议的素材信号在 `AnalysisContext` 已齐备：`primaryStar`（含 `brightness` / `mutagen`）、`mutagenInSanFang`、`currentDx`——推算层不缺输入，缺的只是「从信号到建议句」的确定性一步。

## Goals / Non-Goals

**Goals:**

- 建议 = 确定性推算（信号选择 + 模板槽位填充），同盘可复现、异盘不同、缺失显式降级。
- 两端（`--topic` / `--report`）同源。

**Non-Goals:**

- 流年 / 大限动态预测（`--view` 域）；报告静态论断定位不变。
- 论断句复用为建议句（语义错位，见 D3）。
- 板块结构与渲染版式改动。

## 不可逾越的约束

- **确定性**：CLI 产物不得引入模型生成或随机源——宁可降级收束句，也不产出不可复现的建议。
- **体系立场**：落宫与会照组织，无飞星派口径；建议句不得虚构盘面没有的星 / 化 / 宫（失败可见性纪律：缺失显式，不静默编造）。
- **静态论断边界**：建议不写「今年会……」式时间预测。
- **分层红线**：推算单点住 `analysis/`，渲染层只装配；不反向依赖 `cli/`。

## Decisions

### D1 建议推算收为 `analysis/` 单点，产出结构化条目

新单点（如 `suggestions.ts`，与 `overview-material.ts` 同层的取材/推算单点）输入 `AnalysisContext` + topic，输出 `SuggestionLine[]`（句子已成型 + 依据信号标注），`views/` 与 `report.ts` 只装配不加逻辑。

- **deletion test**：删掉这层，信号选择逻辑就得在 `views` 与 `report` 两个编排器各写一遍——是搬家不是消解，成立。
- **接缝判据**：新增一个建议信号源 = 改单点一处；渲染编排零改动，成立。
- **两面**：收益——两端同源、可断言、可测；代价——多一个模块，但其职责单一（建议素材），与 `overview-material` 的存在理由同构。

### D2 最小信号集，不做全量推算

信号只取三样：主宫主星及亮度、主题三方内的本命四化、大限落宫与主题宫关系。每加一个信号源都要答「删掉它会多写几行」——当前三样已足够让 13 主题的建议各盘不同。

- **备选**：把全盘格局、煞星分布、神煞都纳入——**否决**：信号越多模板组合爆炸，维护成本远超信息增量；建议是收束不是二次论断（论断已在前面小节完成）。
- **两面**：收益——模板句数量可控（每主题 2–3 槽位句 + 1 降级句）、断言面小；代价——建议的信息密度有上限，但这正是「收束」的定位。

### D3 新写行动导向模板句，不复用论断分支句

模板句为新写的少量文案（星名 / 宫名 / 化象为槽位）；降级收束句沿用并显式登记（静态表退位为「模板句 + 降级句」承载）。

- **备选**：复用 `structure-content-branches` 的命中分支句做建议——**否决**：论断句是描述性的（「武曲化权，掌财有道」），当建议用（「宜……」）语义错位；且会把建议与语料承载形态硬耦合，违背 proposal 的「无硬耦合」边界。
- **两面**：收益——建议句职责纯粹、与语料解耦；代价——新写约 40–50 条模板句文案，一次性内容工作（内容扩展档验证义务，不重跑内核回归）。

### D4 降级显式登记，不做静默兜底

每主题登记一条通用收束句（覆盖信号缺失组合）；降级发生时建议条目仍标注依据为「无命中信号」——机器可查（断言可数），而非与命中句不可区分。

- **两面**：收益——与「跳过必须看得见」同一纪律，降级可审计；代价——条目结构多一个标注位，渲染层多一行处理。

## Risks / Trade-offs

- [模板句文案质量参差（新写内容）] → 文案走现有 grades / 引文纪律审查面；模板句不含「倪师 + 引号句」形态则不触引文守卫，触即登记。
- [`--topic` 输出变化波及 cli-samples 49 条样例] → 改生成器 + 重导，diff 逐块核对只含建议小节变化。
- [信号组合覆盖不足导致降级率偏高] → 以实测盘统计降级率；若某主题降级率高，增补该主题模板句（数据增补，不动逻辑）。

## Migration Plan

一次性切换（`TOPIC_SUGGESTIONS` 语义退位，两端同源同变无兼容期必要）：推算单点 → 渲染接入 → 确定性断言 → 生成物重导 → 全量验证。回滚 = revert 单 commit。

## Open Questions
