# Spec Delta

## MODIFIED Requirements

### Requirement: 动态节不入库

断语手册库的数据源 SHALL 为内核结构化条目流（`analysis-structured` 能力）：**依赖运行时
时钟的动态条目**（当前大限 / 流年 / 流月）与**本仓知识源之外的节**（盘面组合矩阵等外部
数据源仓专属内容）SHALL NOT 进入断语手册库——排除由「直出链只取纯命盘条目」在源头承载，
SHALL NOT 依赖对渲染文本的节名黑名单过滤（文本不再入库，黑名单机制随文本解析一并退役）。

#### Scenario: 重建库后无盘面定制行

- **WHEN** 以结构化直出链重建断语手册库
- **THEN** 库内无盘面定制内容与当前大限 / 流年 / 流月条目，静态节内容与迁移前（黑名单
  过滤后）语义一致

#### Scenario: 黑名单命中即不入库

- **WHEN** 内核条目流中出现本仓知识源之外的节内容（如组合矩阵）或时钟依赖条目
- **THEN** 直出链在源头即不导出该类条目（`clockDependent` 标记与节槽边界承载），
  无需维护任何文本形态的黑名单或分类器补丁

#### Scenario: 内核演进不再需要黑名单补丁

- **WHEN** 内核新增一个节或调整节内形态
- **THEN** 结构化条目自动携带其语义字段，直出入库无需补丁

### Requirement: 断语行级规范化承载

断语手册库 SHALL 以**语义列**承载断语：主题、归属主星、节槽、主语星、亮度、化曜、落宫
各自独立成列或字典表，行文本存渲染原行（保证组装与检索输出与文本投影逐字一致），每行按
「主题 × 归属主星 × 序」定位；完全相同的行文本跨主题、跨主星 SHALL 只存一份（字典共享）。
行内语义（亮度/化曜注记）SHALL 入语义列供字段级查询——正文级拆分（剥前缀注记共享）属
渲染契约重构，不在本能力内。

#### Scenario: 行级可查询且组装等价

- **WHEN** 以主题与归属主星为条件查询语义行并按节槽组装
- **THEN** 组装结果与渲染契约（`OracleStar` 字段序与内容）一致，检索行文本与
  本仓内核的渲染输出逐字同源（`getTopicAnalysis` 同盘同参可复现）

#### Scenario: 内容面口径切换（实施期决策留档）

- **WHEN** 对比 schema v1（数据源 = 外部数据源仓 tar 的渲染文本）与 v2（数据源 =
  本仓内核直出）的行文本
- **THEN** 节体系同构但行文本措辞系统性不同——v1 措辞来自外部仓的渲染器实现
  （本仓内核不含该文案表，修订链对 v1 本就断裂）；v2 行文本与本仓内核逐字同源，
  内容真相源真正收回主仓。措辞基准切换是该决策的显式代价，逐条可溯内核数据表

#### Scenario: 共享文本单份存储

- **WHEN** 跨主星存在完全相同的行文本（如通用免责声明）
- **THEN** 行文本在字典中仅存一份，各行经引用指向它
