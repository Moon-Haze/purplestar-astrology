# Design

## Context

`2026-11-22-comment-ratio-limit` 已落地「注释占比 30%、不设豁免」纪律，但口径写成「注释行数 / 非空行数」。用户指出这是对规范的误解——要求的是内容（字符）占比。按行数口径降比会把注释压成单行（内容不变、可读性尽毁），已明确否决并回滚。本变更纠正口径定义，阈值与纪律不动。

## Goals / Non-Goals

**Goals**: 把度量口径从「行数比」改为「注释纯文字字符 / (注释纯文字 + 代码) 字符」（定义 A）；三处规范面（spec / AGENTS / config）口径一致；口径可复现。

**Non-Goals**: 不改阈值 30、不设豁免、生成物边界等纪律；不在本变更内批量改源码，不在本变更内实际降比。

## 不可逾越的约束

- 阈值 30 为 spec 单一登记值，度量脚本从 spec 读取，不写死。
- 口径定义以用户选定为准：注释纯文字 / (纯文字 + 代码)，均去空白、去语法标记。
- 不设豁免清单；契约文档密集文件精简后仍超标的，按「存量超标文件」场景如实列报。

## Decisions

### D1：内容口径选定义 A 而非 B

- **定义 A（选定）**：注释纯文字 / (纯文字 + 代码)，去掉语法标记与全部空白。更贴合「内容」二字，实测 56/159 文件超标。
- **定义 B（否决）**：注释原始字符（含 `/** */` 标记）/ 文件全部字符去空白，实测 69/159 超标。用户已选定 A。
- **代价**：A 的口径实现依赖词法扫描器识别注释区间并去标记，比行数口径复杂；校验器已具备 scanner 能力，可复用。

### D2：排版手法不改变占比

- 分子分母都去空白，压缩行数、增删空行、调整缩进都不改变占比；从定义上堵死「压行降比」的钻空子。

### D3：契约文档密集文件的存量列报

- 精简正文后仍超 30% 的类型定义文件，按既有「存量超标文件」场景如实列报，不删必需字段文档、不设逐文件豁免；与用户「降能降的、剩下如实列报」一致。

## 三问核验

- deletion test：删掉本变更，spec 仍写着错误的行数口径，度量与规范脱节，故必须改。
- 接缝判据：无新扩展点，不适用。
- 抽象 justify：口径定义属规范真相源，删除后无单一定义，故有存在价值。

## Risks / Trade-offs

- [口径切换后存量数字变化] → 从 89/159（行数）变为 56/159（内容 A），两套数字不混用，报告里标明口径。
- [实现层降比与契约文档冲突] → 由「存量超标文件」场景兜底，不删文档、不伪装达标。

## Migration Plan

本变更：修正 spec 口径 + 三处规范同步。后续：另立实施变更按定义 A 实测的 56 个超标文件逐批处理，每批跑剥注释 token 对拍与 typecheck / selftest / npm test 三件套。
