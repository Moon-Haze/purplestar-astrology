# code-style Delta

## MODIFIED Requirements

### Requirement: 注释占比上限

手写 `.ts` 源文件的注释占比 SHALL NOT 超过 **30%**。占比按**内容（字符）**度量，定义为「注释纯文字字符数 / (注释纯文字字符数 + 代码字符数)」：

- **注释纯文字**：由词法扫描器识别出的每个注释区间（`//`、`/* */`、`/** */`），去掉语法标记（起始 `/**` `/*` `//`、续行前导 `*`、`*/` 结尾）后剩下的文字；
- **字符数**：分子、分母一律去除全部空白字符（空格、制表、换行）后计数——空行与排版缩进不参与比例，不用换行或压缩行数的手法改变占比；
- **代码字符**：文件去掉全部注释区间后剩余的文本，同样去空白。

`30` 为单一登记阈值，调整须改本 spec，不得各文件各自为政。**本 requirement 不设按文件或按类别的豁免清单**；生成物由「改生成器重导」纪律管辖，本就不手工维护。

#### Scenario: 阈值违反

- **WHEN** 某个手写 `.ts` 的注释占比经度量脚本按上述内容口径统计 > 30%
- **THEN** 该文件判为违规，需精简注释正文、或把长篇说明外置到 `docs/code/` 并在源码留一行指针后复测，直到占比 ≤ 30%；不得靠把注释压成单行、增删空行等排版手法改变占比

#### Scenario: 度量口径可复现

- **WHEN** 对同一文件用同一度量脚本跑两次
- **THEN** 两次输出的注释纯文字字符数、代码字符数与占比完全一致；阈值 30 由脚本从本 spec 登记值读取，不写死在脚本里；语法标记与空白的剔除规则固定且公开

#### Scenario: 存量超标文件

- **WHEN** 文件在本 requirement 生效前已超标
- **THEN** 不设豁免条目，后续每次改动该文件时同步收敛占比至 ≤ 30%；未改动期间由度量报告如实列报，不伪装达标。若文件的注释几乎全是规范要求的契约文档（文件级、导出符号、函数标签、结构体字段），精简正文后仍无法达标，则如实列报为存量超标，不删必需文档、不设逐文件豁免

#### Scenario: 阈值调整

- **WHEN** 需要把 30% 改为其他数值
- **THEN** 只改本 spec 的登记阈值，度量脚本随之读取新值，不出现多套口径
