# Proposal

## Why

`2026-11-22-comment-ratio-limit` 把「注释占比 30%」的度量口径写成了「注释行数 / 非空行数」。用户指出这是对规范的误解：要求的是**注释内容量**占源文件 30%，不是行数。按行数口径去降比，做法会变成把注释块机械压成单行——内容一字不少、可读性尽毁，是钻空子，已被用户明确否决并全部回滚（工作树 0 改动）。本变更只纠正度量口径定义，把「行数比」改为「内容（字符）比」，阈值 30 与不设豁免的纪律不变。

## What Changes

- **`code-style` spec 的「注释占比上限」requirement 修正度量口径**：占比定义为「注释纯文字字符 / (注释纯文字 + 代码) 字符」——注释文字去掉 `/**` `*/` `//` `*` 等语法标记、分母分子均去除所有空白字符；`30` 仍为单一登记阈值。
- **场景同步**：阈值违反 / 度量口径可复现 / 存量超标文件 / 阈值调整四场景的表述从「注释行」更新为「注释内容字符」，纪律（不设豁免、存量随改动收敛、阈值只改 spec）不变。
- **规范指针同步**：`AGENTS.md`「注释形态」节与 `openspec/config.yaml` apply guidance 两处指针的口径表述同步改为「注释内容字符比」。

### 不做什么

- 不改阈值 30、不设豁免、生成物由「改生成器重导」管辖等既有纪律。
- 不在本变更内批量删改任何 `.ts` 源码注释——降比实施另立变更，逐批跑保真校验与三件套。
- 不采用「注释原始字符（含语法标记）/ 文件全部字符」的备选口径（用户已选定去掉标记、只看纯文字的定义）。

### 被否决的备选方案

- **保留行数口径**：用户明确指出「是内容的 30% 不是行数的」，且压行降比是钻空子，故否决。
- **口径 B（注释原始字符含标记 / 文件全部字符）**：用户选定定义 A（纯文字 / 纯文字+代码），故否决。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `code-style`: 「注释占比上限」requirement 的度量口径从「注释行 / 非空行」改为「注释纯文字字符 / (注释纯文字 + 代码) 字符」（定义 A），阈值与纪律不变。

## Impact

- **规范面**：`openspec/specs/code-style/spec.md`（archive 折回后修正「注释占比上限」requirement）。
- **纪律面**：`AGENTS.md`「注释形态」节、`openspec/config.yaml` apply guidance 两处口径表述同步。
- **验证义务申报**：纯规范面口径纠正，无代码行为变化；验收为 `openspec validate --all --strict` + 度量脚本按新口径实跑确认可复现（同一文件两次一致）。
