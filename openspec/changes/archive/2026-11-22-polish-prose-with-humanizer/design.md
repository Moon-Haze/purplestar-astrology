# Design

## Context

`humanizer-zh` 是用户级编辑技能（`~/.agents/skills/humanizer-zh`）：对**已有中文文本**做
去模板化润色，自带两条与本仓强相关的约束——①不新增原文没有的事实（防编造）②默认只编辑
散文正文，代码块 / 行内代码 / 命令 / 路径 / 标题层级 / front matter 保持原样。本仓另有两条
技能不知道的本地红线：引文纪律（引文守卫扫 `.md` 全树）与 `SKILL.md`↔`references/` 双向
一致断言。设计要回答的是：规则落在哪、豁免线划在哪、怎么在流程里被发现——见 proposal.md
的 Why 与被否决备选，此处不重复。

## Goals / Non-Goals

**Goals:**

- 行文纪律有单一规范出处（code-style spec requirement），且在三处必读面可见：
  spec（细则）/ `config.yaml` apply guidance（apply 时必读）/ `AGENTS.md`（每会话必读）
- 豁免线与本仓既有守卫零冲突：引文、生成物、行为规范文档、单行注释不进润色面

**Non-Goals:**

- 不加机器守卫、不写润色脚本、不改 `humanizer-zh` 技能本身（proposal「不做什么」）
- 不追溯润色存量文档：规则自归档起对**新增**成稿生效，存量只在顺手触碰时顺带

## Decisions

**D1 三层落点各司其职，不引入新机制。** requirement 是规范细则；`config.yaml`
`operations.apply.guidance` 一行 advisory——openspec apply 流程必读面，是「写文档 / 注释」
行为最高频的发生场景；`AGENTS.md` 项目约束一行——纪律的单一真相源，离开 openspec 工作流
的会话也可见。三处指向同一 requirement，不复制细则（AGENTS 只留一行指针口径）。
备选「只写 spec 一处」被否：spec 只在 openspec 工作流中被读，纪律会事实失效。
后果两面：收益是三处必读面全覆盖；代价是归档时要同步三处文本，漂移风险由
「spec 为细则、另两处为指针」的定位压到最低。

**D2 润色时机 = 成稿后、交付前，对象 = 散文正文。** `humanizer-zh` 是编辑器不是生成器：
先让初稿落住（技术事实在此时确定），再对散文过一遍。与技能自身工作流（通读 → 只改存在的
表达问题 → 对照检查）一致，也把「改坏术语 / 引文」的风险压到最小——技术文本被技能自身
规则保护，本地红线再由 scenario 显式钉住（引文保护场景以引文守卫绿为可验判据）。

**D3 豁免线按「润色成本 / 收益 + 既有守卫冲突面」划定。** 单行 why 注释（一行没有润色
空间）、生成文件（生成物不手改既有纪律）、`SKILL.md` / `references/`（改文风会破坏参数面
契约与双向一致断言的锚点文字）——三者豁免不是给偷懒留口子，是避免润色与既有闸门打架。

**三问：** deletion test——删掉这条纪律，行文质量回到凭临场自觉，是缺口不是搬家；
接缝判据——后续调整适用面 / 豁免面 = 改 requirement 文本一处，不需要动第二个文件；
抽象 justify——零新抽象，纯流程纪律。

## Risks / Trade-offs

- [流程纪律无机器强制，漏跑无人察觉] → 接受并留档：与「不夹带 format」「最小 diff」同级
  的自律纪律；评审走查时对照 requirement 场景核
- [润色改坏术语 / 引文 / 锚点] → 双保险：技能自身文件保护规则 + 引文守卫兜底（改了引语
  `npm test` 层 7 当场红）；scenario「引文保护」把守卫绿写成可验判据
- [规则让人把润色当「去 AI 味」仪式，为改而改] → requirement 写明与技能口径一致：
  没有问题的段落原样保留，不为展示工作量强改

## 不可逾越的约束

- 引文纪律：倪师引语与 `corpus/data/annotations.ts` 登记条目在润色中不可动（引文守卫兜底）
- 生成物纪律：`docs/manual/` 等生成文件不手改，润色豁免
- `humanizer-zh` 技能自身约束不可被本规则放宽（不新增事实、保护面保持原样）
