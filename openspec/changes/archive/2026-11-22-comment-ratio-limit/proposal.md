# Proposal

## Why

`code-style` spec 已要求源码内有 `@file`、导出符号文档、函数标签与结构体字段注释；注释量随之上升。实测 159 个手写 `.ts` 中 89 个（56%）注释行占非空行比例已超 30%，最高 82.8%。缺少统一的数量纪律，注释会持续膨胀，最终压制代码可读性。用户拍板：新增一条**全仓统一、不设豁免**的注释占比上限规范。

## What Changes

- **`code-style` spec 新增 requirement**：手写 `.ts` 文件的注释占比（注释行 / 非空行）SHALL NOT 超过 30%；阈值单一登记、不设按文件或按类别的豁免清单。
- **度量口径固化**：注释行 = 整行 `//` / `/* */` / `/** */` 及续行 `*`；非空行作分母；统计以脚本实跑自报为准，不写死文件数。
- **存量处置**：当前超标文件须在后续改动中收敛到阈值内；本变更只建立规范与度量口径，逐文件降比另立实施批次，不在本变更内批量删改注释。
- **生成物边界**：`wenmo-tables.ts` / `tianji.ts` 由「改生成器重导」纪律管辖（`AGENTS.md`「项目约束（不可动）」），本规范对手写文件生效；这不构成按文件豁免，而是生成物本就不手工维护。

### 不做什么

- 不在本变更内批量删改 89 个超标文件的注释——那是实施批次，不是规范面工作。
- 不改变刚生效的 `@file` / 导出符号 / 结构体注释要求——占比收敛须保留类型约束与防错信息，不删必要文档。
- 不引入 Doxygen 工具链。

### 被否决的备选方案

- **只约束新增改动、存量豁免**：用户明确要求不设豁免、一个标准，故否决。
- **只计散文注释、标签行不计**：实测仍有 81/159 超标（51%），放宽口径不能解决膨胀问题，且口径复杂难核验，故否决。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `code-style`: 新增「注释占比上限」requirement（阈值 + 度量口径 + 存量处置）。

## Impact

- **规范面**：`openspec/specs/code-style/spec.md`（archive 折回后）。
- **纪律面**：`AGENTS.md`「项目约束（不可动）」与 `openspec/config.yaml` apply guidance 同步指针（按 42b336f / a70d305 先例三处齐动）。
- **验证义务申报**：纯规范面改动，无代码行为变化；验收为 `openspec validate --all --strict` + 度量脚本实跑确认口径可复现。
