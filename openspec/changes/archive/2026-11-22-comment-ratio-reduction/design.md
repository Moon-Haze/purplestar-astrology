# Design

## Context

`code-style` spec 已把「注释占比 ≤ 30%、无豁免、定义 A（注释纯文字 / (纯文字 + 代码) 字符，去标记去空白）」写为现行规范。三次提交只落规则，实施从没立项。本变更执行这一既有规范，不改阈值、不改口径、不加豁免。

启动前发现度量前提已变：旧 TS scanner 在模板插值 `${expr}` 的 `}` 后不续扫模板正文，把正文里的 `/*.jsonl.gz` 当块注释起点吞掉余下内容，导致其后注释全部漏计、占比虚低。改用独立字符级 lexer（定义 A 真相源）后，超标数从旧口径 51、登记值 56 变为 **87/159**（`scripts/synastry/chart-view.ts` 从假达标 19% 变为 44.5%）。数字跳变已在上游停手上报、用户授权按 87 推进；旧 56 清单作废。

## Goals / Non-Goals

**Goals**：按定义 A 把能降的超标文件降到 ≤ 30%，全程代码零变更；结构冲突文件逐文件列报下限与候选，交用户拍板；度量真相源单一化。

**Non-Goals**：不改规范面（阈值、口径、豁免、生成物边界）；不压行（定义 A 去空白，压行无效）；不删 `@file` / `@param` / `@returns` / `@throws`、docs 指针与引文；不在本变更内提交（提交口径实施后由用户确认）。

## 三梯队与降本分层（定义 A 实测 87）

| 梯队   | 文件数 | 仅外置散文可达标 | 结构冲突（外置后仍超） |
| ------ | ------ | ---------------- | ---------------------- |
| 30–40% | 33     | 26               | 7                      |
| 40–55% | 25     | 5                | 20                     |
| 55%+   | 29     | 0                | 29                     |
| 合计   | 87     | 31               | 56                     |

「仅外置散文可达标」判据：`contract / (contract + code) ≤ 30%`（外置全部散文后的下限）。下限 > 30% 的文件属于结构性冲突——字段文档必留且无豁免，块数与代码行数形成数学死结。

## Decisions

### D1：度量真相源 = 字符级 lexer，单一 `analyze()`

`.script_test/analyze-lib.cjs` 的 `analyze(text)` 是唯一真相源：按字符流状态机处理普通字符串、模板（含 `${}` 嵌套插值）、正则字面量、行/块注释，输出精确区间与纯文字分组。`verify.cjs` 与 `plan.cjs` 都 require 它，全目录不得出现第二份扫描循环。TS7 scanner 仅作 sanity 对拍，不一致时以 lexer 为准。

### D2：降比手段按杠杆排序

1. **外置散文**：把不含 @tag 的长散文块原文搬进 `docs/code/`，源码留一行摘要 + 指路牌。可降 31 个里优先做。
2. **精简契约正文**：在不破坏 JSDoc 语义、不删 @tag、不删引文的前提下压缩冗余措辞（如把重复的前提句合并）。
3. **结构冲突**：不静默删文档、不设豁免，逐文件列报后交用户拍板。

### D3：压行不算降比

定义 A 分子分母都去空白，压行、增删空行、调缩进都不改变占比。禁止把注释机械压成单行冒充降比（那只在行数口径下有效，已被用户否决）。

### D4：工作树既有改动的处理

工作树已有 9 个注释搬迁改动（未提交、不关联 active change），其中 4 个 `.ts` 已降至达标、2 个 (`scripts/synastry/chart-view.ts` 44.5%、`scripts/cli/host/out.ts` 36.9%) 仍超标。这些改动与降比目标重叠但未纳入任何 change。本变更 apply 时把它们作为既有基线纳入统一度量与验收，不重复改写其内容、不擅自替它们归属提交；提交口径随本变更一并交用户确认。

### D5：安全网先自证再放行

`verify.cjs selftest` 五条（原样 PASS / 改代码 CODE-DIFF / 精简正文 PASS / 外置保真 PASS / 丢引文 LOST）全过，证明校验器有区分能力后，才允许它对本变更改动文件放行。每个改动文件逐项过：剥注释代码 token 与 HEAD 基线逐 token 相等、受保护内容逐项仍在、外置正文逐字一致、占比复测 ≤ 30%。

## 实施收口：块级证据推翻 D2 外置假设

D2 假设「31 个文件仅外置散文可达标」。进入技能步 7 逐文件肉眼取证后该假设被推翻：

- `.script_test/dump-groups.cjs` / `.script_test/find-usage-prose.cjs` 的全库扫描显示，`plan.cjs` 判为「散文」的块绝大多数是**字段文档**（紧邻字段的 JSDoc，AGENTS.md「结构体须有字段注释」要求必留）与**防错 why 注释**（解释「为何这样断言/校验，否则错在哪」，用户 m00830 明令不删），不是可外置的叙述正文。
- 例：`tools/db/build-duckdb.ts` 54 组 / 7155 字几乎全是 why（「少退一层就 ENOENT」「非法值必须报错」「事务 aborted 次级异常」）；`tools/review-gate.ts`、`scripts/cli/selftest/args.ts`、`test/lib/compare.ts` 同类；`tools/db/shard-format.ts` 24 块、`scripts/cli/args/table.ts` 41 块是字段文档。
- 真正的纯用法头全库仅 6 组 28–189 字碎片，且混有 spec 指针/why，无 `query.ts` 那样的连续可外置块。

**收口决定**（用户技能步 7 拍板）：保留 `query.ts` 唯一合规降比实例；其余 86 个超标文件全部列入 `structural-exceptions.md` 如实列报，不批量外置或精简。D2 的「外置散文降 31 个」与三梯队批量降比计划不再执行；D3/D4/D5 纪律不变。

## 三问核验

- deletion test：删掉本变更，87 个超标文件无人处理、规则悬空，故必须做。
- 接缝判据：无新扩展点，不适用。
- 抽象 justify：度量真相源单一化消除多份扫描循环的数字漂移，删除它就退回 51/56/87 混用，故有存在价值。

## Risks / Trade-offs

- [口径修正导致数字与旧清单不一致] → 旧 56/51 一律作废，报告与 proposal 留 51→87 前后对照与根因机制。
- [外置散文到 docs/ 破坏可读性或引文] → `@tag` 与引文留在源码、只外置纯散文；保真校验逐字比对，丢引文必须 FAIL。
- [结构冲突文件无解] → 如实列报下限与候选，不伪装达标、不设豁免；用户拍板后才动。
- [工作树既有改动与本变更多重来源] → D4 纳为基线统一度量，不擅自归属提交。
- [用户推翻列报决策] → m01192「都修改」要求全量精简改写。收口采用「语义红线、数字目标」：能保语义达标的 75 个全部达标，真无解的 12 个如实列报（4 floor>30% + 3 // 锁定 + 1 下限 + 4 字段密集存量），不伪装达标、不保持 HEAD 不动（best-effort 落盘）。D2「外置散文」被「精简改写措辞」取代；docs-adjusted floor 纠正 lockfloor2 把 docs 已留存 token 误计入源码 floor 的保守误判，翻案 4 个原判 IMPOSSIBLE 文件。

## Migration Plan

1. 度量真相源自证（硬闸门，已完成）→ 2. 三梯队分批降比，每批跑剥注释 token 对拍 + 三件套 → 3. 结构冲突列报交拍板 → 4. 全量复测（剩余超标 0 或仅经确认的例外）→ 5. 归档改回 spec 无需（本变更不改规范面）→ 6. 提交口径由用户确认。

## Open Questions

- 56 个结构性冲突文件如何处理（外置+精简后仍超 30%）：等用户逐批看过下限与候选后拍板——维持原样如实列报 / 进一步删非必须散文 / 其他方案。
- 工作树既有 9 个注释搬迁改动的提交归属：等用户在实施完成后统一确认。
