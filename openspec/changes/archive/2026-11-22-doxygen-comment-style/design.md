# Design

## Context

见 proposal.md 的 Why。现状扫描显示三处源码目录共有 1281 个 `/**` 起点、28 个普通 `/*` 起点；`@param`、`@returns`、`@remarks`、`{@link}` 已广泛使用，`@packageDocumentation` 与 `@throws` 也在现行源码中出现，而 `@file` 尚未使用。技术前提不变：本仓采用 Doxygen/JSDoc 兼容子集，不引入新工具链。

## Goals / Non-Goals

- **Goals**：统一文件级 `@file`；保留已有有效注释与标签；明确哪些注释不参与转换；用覆盖清单、基线对拍和反向自测证明代码与受保护内容均未丢失。
- **Non-Goals**：不批量转写普通解释性注释，不清理既有行内注释，不补全所有符号的 API 文档，不改变运行时行为。

## 不可逾越的约束

- 生成物不手改：`scripts/data/wenmo-tables.ts` 与 `scripts/corpus/data/tianji.ts` 跳过；`docs/cli-samples.md` 不在本次源码范围内。
- 引文纪律优先于行文润色：倪师引文及归属逐项保真。
- 注释指针有效性守卫盯的指针不得丢失或改义。
- 不触碰任何代码 token，包括 shebang 的位置、注释掉的代码与工具指令注释。
- 新增散文仅限缺失文件头处的一句话 `@file`；若确需新增成段散文，先暂停并统一经 humanizer-zh 润色，再另行确认范围。

## Decisions

### D1：以 `@file` 为统一锚点，既有文档正文不套模板重写

- **收益**：补足文件级导航与编辑器悬停，保留现有 JSDoc 投资，避免把风格统一变成全文重写。
- **代价**：不同文件的说明详略仍不完全一致；详略属于内容质量问题，不在本次形式规范中强求。
- **否决备选（全仓批量转写）**：现有 JSDoc 已占多数，批量转写的审阅和语义丢失成本高于收益。

### D2：标签集是最低约定，不是封闭白名单

文件头使用 `@file`；参数与返回值继续采用既有 `@param` / `@returns` 形态。已有 `@packageDocumentation`、`@throws`、`{@link}` 等有效标签原样保留，不为了凑齐标签清单而新增空泛说明。

- **收益**：不会误删有效文档，也不会为统一形式产生照签名复述的注释。
- **代价**：标签种类仍随真实文档需要而不同，不能靠一张固定清单机械判定所有注释。
- **否决备选（封闭标签白名单）**：会把已有有效标签误判为不合规。

### D3：按注释承载的语义分类，而非按起止字符批量替换

分类顺序固定为：shebang 与工具指令、注释掉的代码、许可证；文件级文档；符号级文档；普通块注释、行内与行尾解释。前三类原样保留，文件级只补 `@file`，其余解释性注释留给后续相关改动渐进整理。

- **收益**：避免把可恢复代码或指令改成失效文本。
- **代价**：迁移前需生成并审阅文件清单，不能用一个替换脚本直接跑全仓。
- **否决备选（按 `/*` 统一替换为 `/**`）**：会误伤普通块注释、行尾说明和注释掉的代码。

### D4：校验代码保真与注释受保护内容保真，二者不能互相替代

临时校验器放 `/tmp`，以 `git show HEAD:<file>` 为基线。代码侧使用 TypeScript 扫描器剥除注释 trivia 后逐文件比较；内容侧分别抽取并归一化 `.md` 指针、命令指针、测试文件指针、引文及归属，以多重集对拍，允许仅为 `@file` 新增的内容。校验器列出 `expected / changed / skipped` 文件及计数，缺失基线、解析失败、空扫描和未预期跳过均失败。

正向自测要求未改文件通过；反向自测分别临时修改一个代码 token、删除一个指针、删除一条引文或归属，必须失败。字符串中的注释样文本、行尾注释与普通块注释纳入扫描器自测，避免注释范围识别错误。

- **收益**：代码不变与内容不丢分别有证据，既有测试未覆盖的丢失也能被发现。
- **代价**：一次性校验器开发成本高于单纯跑三件套；校验器只保证受保护面，不能代替人工判断新增 `@file` 是否准确。
- **否决备选（仅靠既有守卫）**：现有守卫不比较基线与工作区的指针、引文数量，删除内容也可能全绿。

### D5：按文件头缺口分批，完整三件套只在集成终跑

先盘点并冻结缺失 `@file` 的文件清单，再按 `scripts` → `test` → `tools` 分三批补文件头。每批运行校验器与 Prettier 检查，并阅读该批全部文件头；集成终跑再执行 `typecheck`、`selftest`、`npm test`、`lint` 和 Prettier 检查。

- **收益**：改动只落在文件头，局部校验足以拦截批次问题；完整回归集中执行，避免为纯注释改动重复付出相同成本。
- **代价**：批次之间不跑完整测试，若校验器有漏洞会晚到集成阶段暴露，因此反向自测必须先于迁移完成。
- **否决备选（每批完整三件套）**：对只补文件头的批次增加重复等待，不增加新的语义证据。

## 三问核验

- deletion test：不新增仓库内抽象或接缝；临时校验器随本次迁移结束删除，不留维护面。
- 接缝判据：无新扩展点，不适用。
- 抽象 justify：不引入生产代码抽象；校验器的代码与内容对拍分别回答两个不可互替的问题。

## Risks / Trade-offs

- [把全仓文件误列为需要修改] → 先冻结缺口清单，变更文件必须属于该清单；未预期变更或跳过即失败。
- [新增 `@file` 写错职责] → 每批阅读全部新增文件头，不只看统计；无法确认职责的文件暂停并上报。
- [校验器把空扫描或解析失败当成功] → 覆盖计数、显式跳过原因、反向注入与字符串样本文本自测。
- [格式化工具产生无关改动] → 仅运行 `npx prettier --check scripts tools test`，不执行全树 `prettier --write`。
- [新增长说明未经润色] → 本次只允许一句话 `@file`；出现额外成段散文即暂停，不夹带落盘。

## Migration Plan

先生成缺口清单和基线，再完成校验器正反自测，随后按目录补文件头。已有文件头只加 `@file`，缺少文件头才新增整个文档块。每批核对变更清单、校验结果和全部新增文件头，集成终跑执行完整闸门与 `openspec validate --all`，通过后再折回主规范。

回滚按文件还原到 HEAD；不得回滚工作区中其他并行改动。若发现某文件需要重写既有正文才能补 `@file`，该文件退出本批并上报，不顺手扩大范围。
