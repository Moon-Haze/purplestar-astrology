# Design

## Context

现状与动机见 proposal.md 的 Why。设计面的关键现状：

- `test/report.test.ts:74` 已动态加载 `@/cli/args/table`（前案为派生跳过条件引入），
  两根轴的派生复用同一 import，零新增加载面。
- 矩阵循环（`report.test.ts:231-280`）今天的形态：外层分支四元组手抄（:250）、
  内层旗标 4 格手抄（:251-255）、跳过条件已派生（:239-249，前案 D6 成果）、allow
  循环手抄三元组（:269-273）。
- `scripts/cli/args/table.ts` 侧：`EXCLUSIVE_BRANCHES`（:493-508，含 `consumes` 与
  `rejectsWithNote`）与 `SHADOWABLE_KEYS`（:433-443，role 派生：topic-deep 组去
  `noShadow` 的 palaces + output-select 组标 `shadow` 的 8 项 = 13 项）都已就绪，
  本变更零声明表改动。
- `report.test.ts` 的调用是进程内直调（`cliCmdInProcess` / `cmdFails`，:47-65），
  命盘缓存命中后单格毫秒级——封闭枚举的运行成本可忽略。

## Goals / Non-Goals

**Goals**

- 矩阵两根轴 + allow 方向全部改派生，测试面接缝判据（AGENTS.md:307「一个文件 +
  一行注册」）在测试面闭合：加第 5 个独占分支、加被吞旗标、调放行 = table.ts
  一处表态 + 探针映射一行夹具，矩阵自动跟随。
- 覆盖面从 16 格手抄抽样升为 48 格封闭枚举，`table.ts:491` 注释的宣称从假变真。
- 新分支 / 新旗标「未入矩阵」从静默变当场红（缺名守卫）。

**Non-Goals**

- 不改任何 CLI 行为、不改声明表、不改 selftest 断言（`selftest/args.ts` 零改动）；
- 不新增测试文件、不登记层表 / LAYERS；
- 不做 `--info` 上级梯行为钉点（5 号发现留作后手，可复用本派生骨架）；
- 不做格级逐字节文案对拍（includes 双子串契约面维持）。

## 不可逾越的约束

- **失败可见性**（AGENTS.md:251-252）：缺名守卫把「未入矩阵」变成当场红；新增格
  断言不成立时按缺陷处理，不得加跳过格掩盖。
- **计数类事实不写死**（AGENTS.md「SKILL.md 与 CLI 的耦合」节）：矩阵格数从派生
  轴计算自报。
- **最小 diff**：只动 `test/report.test.ts` 既有 describe 内的循环与映射，不夹带
  无关排版改动。
- **抽象判据**（AGENTS.md:305-306）：探针映射是夹具不是声明副本（见 D2），不引入
  身兼两职的常量。

## Decisions

### D1：三根轴的单一来源映射，循环只做投影

```text
分支轴   ← EXCLUSIVE_BRANCHES.map(b => `--${b.name}`)      // table.ts:493
旗标轴   ← SHADOWABLE_KEYS（kebab 原名 → `--<key>`）        // table.ts:433
allow    ← EXCLUSIVE_BRANCHES 中 consumes 非空的条目
skip 规则 ← flag === branch（自指）
           ∪ flag ∈ entry.consumes（放行 → allow 循环分管）
           ∪ flag ∈ entry.rejectsWithNote?.keys（bespoke → 既有子串钉点分管）
```

前案 D6 的派生 skip 保留并补自指一项。格数账：4 × 13 = 52，减 3 自指
（topic / report / info 自指；palaces 标 `noShadow` 不在旗标轴、不产生该格）
减 3 放行减 1 bespoke = **45 格通用断言**，加 allow 3 格共 48 格——与任务说明
「约 45 格」精确吻合。

### D2：两张探针映射是夹具，不是第三份手抄

- **分支取值映射**：`--topic` 需要主题值 → `{ topic: ["love"] }`（其余分支裸旗标）；
- **旗标值映射**：值形态旗标的合法样本值 → `{ ages: "34", daily: "10", decadal: "2",
  focus: "财帛", hourly: "3", monthly: "5", topic: "love", view: "daxian",
  yearly: "2027" }`（switch 形态的 mutagen / pattern / info / report 不带值、
  不需要条目）。

**为什么不算手抄副本**：两张映射不重复判定链的任何决策（谁被吞 / 谁放行 / 谁优先
都在 table.ts），只补「怎么调用」的夹具信息——语义与声明表零重叠。漂移风险由
**缺名守卫**兜住：遍历派生轴时对映射缺席条目 `assert` 当场红，与失败可见性同构
（类比「参数拼写错报错并给最近邻建议」的纪律——测试夹具缺席也是显式失败）。
switch / value 的判定依据声明表 `kind` 字段，不另立清单。

### D3：缺名守卫的形态

守卫不做在声明表侧（selftest 已守内部一致性），做在矩阵循环入口：任何派生条目
在映射中缺席即 `assert.fail("…未登记探针取值，新分支/旗标未入矩阵")` 并点名。
「新分支未入矩阵即红」由此成立——第 5 条分支加入 `EXCLUSIVE_BRANCHES` 而测试面
未登记时，矩阵测试红，而非静默少一列。

### D4：新增格的接纳程序（探针先行，落地即绿）

本会话已对全部 48 格实跑探针（bash 循环逐格跑 CLI、断言「点名 + 不会生效」子串 /
「本宫主星： + 无误伤」），**45 + 3 格全绿**（含此前未覆盖的 32 格与 3 个自指格
的判重行为核实）。落地时矩阵直接以封闭枚举形态出现，不需要过渡期抽样。
此后新增格的接纳程序：改声明表 → 跑矩阵 → 若新格红，先实跑探针判别是「夹具缺席」
（补映射）还是「次序缺陷」（修分发，按失败可见性处理）——不存在第三种「加跳过」
的选项。

### D5：职责分工维持前案格局

selftest/args.ts 的声明完整性断言（放行 ⊆ 被吞域、分支名已声明、派生文案与冻结
镜像一致）守声明表内部一致性；本变更的行为封闭枚举守测试面对声明表的跟随。
两层都不管的缺口——「矩阵轴是否跟声明表走」——正是本变更补上的第三块板。

## 三问自检（config.yaml rules）

- **deletion test**：删掉派生（回到手抄轴）= 分支轴 / 旗标轴 / allow 白名单三份
  手抄副本回来，正是 d6827fc / da4a449 漏格根因的温床——复杂度集中（守卫密度）
  而非搬家。删掉探针映射 = 值形态旗标无法调用、缺名守卫失去标的——不是冗余。
- **接缝判据**：落地后加第 5 个分支 / 加被吞旗标 / 调放行 = `table.ts` 一处表态
  （+ 探针映射一行夹具 + 缺名守卫当场红指路），矩阵、allow 循环、skip 规则零协同
  ——「一个文件 + 一行（项）」在测试面成立，AGENTS.md:307 的判据不再有测试面例外。
- **抽象 justify**：删掉两张映射会多写「每个格手拼 argv」的散抄与静默漏格风险，
  答得出，立得住。

## Risks / Trade-offs

- [封闭枚举运行时长增加（16 → 48 格，进程内直调）] → 命盘缓存命中后毫秒级/格，
  实测成本可忽略；若未来格数增长到秒级/格，先怀疑越界（分支数不该这样涨）；
- [探针值映射与声明表 `kind` 判定的形态耦合] → kind 是声明表字段、单一来源，
  映射只补值；`optionalValue` 旗标（如 topic 裸开关形态）统一按带值调用，不影响
  被吞语义；
- [allow 循环泛化后对新分支的断言语义（「本宫主星：」）不一定适用] → 该子串是
  --topic 主题论断的形态契约；若新分支的放行产物形态不同，实现时以该分支的实际
  形态契约替换断言子串并在注释指名——这是新增分支时的显式表态，不是静默跟随；
- [矩阵 it 内格数从 13+3 升为 45+3，失败输出更长] → 断言消息已点名分支与旗标，
  定位粒度不变。

## Migration Plan

单仓单步落地，无部署面：`test/report.test.ts` 既有 describe 内先加两张映射与
缺名守卫，再把三根轴与 skip 规则改派生，跑 `npm run typecheck` → 矩阵单测
（`node --test test/report.test.ts` 或 `npm test`）全绿 → lint 对改动行。
回滚 = 还原单 commit。
