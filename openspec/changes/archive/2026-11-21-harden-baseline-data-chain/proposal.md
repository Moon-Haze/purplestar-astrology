# Proposal

## Why

上一个 change（expand-db-baseline-regression，2026-11-21 归档）实施期实证了一类结构性缺陷：**答案册（基准数据）自身没有守卫**。db/dataset 数据集曾在某次重建中从 1924–1983（518,400 条）静默变为 1950–2026（674,976 条），没有任何测试报警——是实施中档工具时偶然撞见的，而非任何闸门捕获。衍生后果有三：

1. **fixtures 重建流程实质断裂**：重建按 1924 年起步抽取，而库中 1924–1949 不存在——重建必产出不足 300 条，日常回归的「300 条」硬计数断言当场红；「升级引擎 → 重建基准」这条既定流程今天走不通。
2. **数据集血统无记录**：新数据集由谁、何时、用什么引擎版本生成，没有任何登记；只有「重叠区 3,000 条实测与现行内核零差异」的间接证据。
3. **文档计数与实况漂移**：README / AGENTS / 全量脚本标签仍写 518,400 条与 1924–1983。

另有普查工具的流程性弱点：分歧分布表只输出当下、不与上次对拍，整表换版或单格修订的变化范围靠肉眼。

## What Changes

- **数据集指纹对账（P0）**：重建数据集的导出工具在导出时**自动登记**指纹——samples.parquet 与 palaces.parquet 的字节 sha256 + 总条数 + 年份范围 + 生成日期 + 血统备注；日常回归新增一条断言读文件字节算哈希对账（**只读文件字节，不查库内容**——日常回归不因此引入 DuckDB 原生依赖，守住「npm test 什么都不需要」）。数据集再被以任何方式动过而未重登记 → 第一次跑 `npm test` 当场红。
- **基准范围正式化（P0）**：正式采纳 **1950–2026** 为基准范围（拍板依据：本机 tar-shards 仅存 1950–2026 共 78 个年份目录，1924–1949 原始分片已不在盘上，A 方向「补回缺年」本地不可行；数据链——数据集 / 分片 / topics——已整体前移，此为对既成事实的显式追认）。落地三件事：
  - 重建 fixtures：抽样年份改为 1950–2026（77 年 × 5 条 = 385），走 `build-fixtures` 既有的**写盘前分歧自检**（若新数据集引擎血统与现行内核不符，会当场红而非静默固化——这正是血统的实证闸门）；
  - 硬计数改派生：chart.test 的「300 条（60 年 × 5 条）」改为从 manifest 派生（对齐 quality-gates 计数纪律；「新增或退役测试文件」同类修法的延伸）；
  - 文案同步：README / AGENTS / 全量脚本范围标签 / 重建工具常量等全部计数与年份陈述与实况对齐。
- **普查基线对拍（P1）**：普查工具支持「存基线 / 对基线」两种形态——基线 JSON 入库，重跑时与上次分布表 diff，文墨表修订或换版的变化范围一眼可辨。
- **Deferred（上游受阻，本次不实现）**：
  - 文墨亮度表提取器重跑逐格验证——提取脚本在 `reference/ziwei-samples-toolkit`（上游 private 仓），**本机该目录不存在**；恢复条件：上游仓重新可用后执行。
  - 真太阳时 / 晚子时的语料级覆盖——需上游 toolkit 以多经度 / 晚子时辰生成新样本；同样待上游可达。

### 不做什么

- **不动排盘内核与依赖**——CACHE_VERSION、iztro / lunar-typescript 版本零改动。
- **不把亮度拉回对拍**——口径冲突维持既有结论，亮度仍由锚点 + 信息级普查守护。
- **不尝试从上游网络拉取 1924–1949**——可行性未知且数据链已整体前移，追认 1950–2026 是与实况一致的最小动作；若将来上游补了旧年份，届时再显式扩范围（本变更的指纹登记面会记录数据集版本，扩范围同样是显式动作）。
- **不扩大日常样本量**——385 条由「77 年 × 5 条」的既定抽样设计自然得出，不为覆盖率刻意加码；覆盖扩张仍归中档 / 全量档。
- **不新增能力 spec**——全部落 `quality-gates` 既有能力修订。

## Capabilities

### New Capabilities

（无——指纹对账与普查基线都是验证基建行为，归 `quality-gates`。）

### Modified Capabilities

- `quality-gates`：
  - **新增** Requirement「数据集指纹对账」（导出工具自报登记 / 字节哈希对账不引原生依赖 / 指纹不一致当场红并指路 / 血统元数据随指纹登记）；
  - **修订** Requirement「亮度分歧普查」（补「基线对拍」形态：可存基线、可对基线，变化组合逐条点名）。

## Impact

- **修改** `tools/db/build-duckdb.ts`（导出时自报登记指纹）、`test/fixtures/manifest.json`（登记面扩展：数据集指纹节）、`test/chart.test.ts`（硬计数改派生）、`test/lib/run.ts` 或新增断言所在文件（指纹对账断言，归层 6 仓库自洽——它读的是登记面与文件字节，不属排盘对标）、`test/tools/brightness-census.ts`（基线形态）、`test/tools/build-fixtures.ts`（抽样年份常量）、`test/tools/full-corpus.ts`（范围标签改自报）、`test/README.md`、`AGENTS.md`（计数与年份陈述）。
- **重建产物**：`test/fixtures/charts.jsonl` 与 `manifest.json` 重导（走分歧自检，diff 只应含预期变化）。
- **不触** `scripts/` 内核导出、依赖版本、CLI 行为面。

## 验证义务申报

**内容扩展档偏上**（数据面重建 + 工具改动，不触内核导出）：`npm run typecheck` + `node scripts/purple-star.ts selftest` + `ZIWEI_NO_CACHE=1 npm test` 三件套全绿；fixtures 重建走分歧自检全绿后 diff 审阅（diff 应只含样本集换血与 manifest 元数据）；`test:midcorpus` 复跑一次确认双档一致；`openspec validate --all` 零警告。
