# Proposal: 落地 code-style 注释规范（仅预防检查器）

## 背景

`openspec/specs/code-style` 已规定「注释少而精 + 长注释（连续 >10 行）外置 `docs/code/`」。
原想对存量做外置，但审计发现：仓库内 **>10 行连续注释块共 380 个**，去掉文件头/许可证后仍有
约 **296 个非头部块**（`scripts/` 216 · `tools/` 30 · `test/` 50）。全量外置是跨近 300 处的
仓库级大重构——会把 `test/` 的场景描述注释也拆散、制造海量 diff、偏离「注释别太长」的本意。
故本 change 只做**预防**：加一个自动检查器，让「新增/改动文件里出现 >10 行连续注释」在 review
面被拦下；存量零扰动。

## 做什么

- 新增检查器，扫描**本次变更**里 `scripts/` 与 `tools/` 下的 `.ts`（**排除 `test/`**）。
- 判定连续注释块（行内 `//`、块注释 `/* */`、块内 `*` 续行）行长 **> 10 行** 即报一项 finding。
- 排除两类块：**文件头/许可证块**（块起始行 ≤ 5）与 **JSDoc 块**（以 `/**` 起手）。
- 把该 finding 接入 `tools/review-gate.ts` 的机检段（与既有 🔴/🟡/💭 同级），并在 `package.json`
  加 `npm run code-style:check` 独立入口（供人工/CI 单独跑）。

## 不做什么

- **不**外置任何存量注释（~296 块保持原状）。
  - ⚠️ 2026-11-01 实现期修订（实测 + 用户拍板）：296 是未排除 JSDoc 的审计粗口径；按检查器
    真实规则（排除头块 ≤5 / `/**` JSDoc / test/），`scripts/`+`tools/` 存量仅 **8 块**。为使
    `npm run code-style:check` 可达全绿（任务 1.2 判据「清理后 = 0」），这 8 块随本 change
    一并外置（零行为变化，见 tasks §4）。test/ 的场景描述注释仍一律不碰，「全量外置 296 块」
    的否决不变。
- **不**改 code-style spec 的阈值（10 行保持为单一登记值）。
- **不**扫描 `test/` 目录（测试文件的场景描述长注释是 spec 的一部分，不该被外置或告警）。
- **不**动 `references/`、不改业务/排盘逻辑。

## 验证义务

属「新增独立检查 + 轻微改 review-gate」：因改动触及 `tools/` 的 `.ts`，走「中」档——
`typecheck` + `selftest` + `npm test` 三件套必跑；本检查器自身也必须是 review 闸门面的硬项
（注入 11 行注释应非零退出 / 报 finding），否则等于没守。

## 被否决的备选

- **全量外置 296 块**：否决，仓库级大重构、把测试描述也打散、git 噪声巨大，偏离本意（见背景）。
- **用 ESLint 注释长度规则**：否决，仓库 lint 已有既定配置（`eslint.config.mjs`），且 `review-gate.ts`
  顶部「刻意不做的事 ③」明言不做风格判断——引入注释长度规则会与其冲突；跨 `scripts/` 与 `test/`
  的统一扫描也不如独立脚本可控、可注入例外。
- **只做独立脚本不接入 review 面**：否决，独立脚本无人主动跑等于没守；必须进 review 面才有强制力。
