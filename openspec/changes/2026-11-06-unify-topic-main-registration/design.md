# Design

## 三问自检（config 规则）

- **deletion test**：删掉内联两处 set 是让复杂度**集中**——「哪些全文是主场」的答案只剩预扫描
  一份（`getTopicMainContentTexts`），没有新增任何等价物承接（`dedupe` 表、views 消费面、装配
  层调用序全部原样），所以是删而不是搬家。删后 `report.ts` 净减约 8 行（两处 set + 5 行注释），
  未来新增主场全文来源只改预扫描清单一行（`:145`）。
- **接缝判据**：零新抽象（不加函数、不加类型、不加模块）。预扫描清单本就是接缝——「加一个
  主场全文来源 = 改 `:145` 一行」在本 change 后才真正成立（改前必须同时改预扫描与渲染内联两
  处，漏一处即静默回潮 1.4 修过的首现漂移）。
- **抽象 justify**：本 change 只删不加；对拍断言是测试面而非抽象，无「删掉多写几行」问题。

## 不可逾越的约束

- **冻结内核契约**：`analysis/index.ts` 导出面不变（`getTopicReport` / `getTopicMainContentTexts`
  / `ReportOptions.dedupe` / `getTopicReportMeta` / `getDecadalSection` 全保留），层 3
  `kernel-contract.test.ts` 零变动。
- **既有 spec 语义不变**：「论断全文首现原则」「双主星主场展开」「四化注首现原则」「单主题输
  出逐字节不变」的期望值一律不动——本 change 只收敛实现，不改任何 scenario 期望。
- **失败可见性**：删除的是「静默纠正缺失登记」的兜底（且其覆写语义可静默翻转指引目标）；不
  得引入任何新的静默兜底来替代——未来绕过预扫描的调用方缺登记时，应以可见的重复全文暴露，
  而非被悄悄纠成首现抢主场。
- **分层红线**：analysis 知识层改动，不触排盘内核与 CLI 分发；层 1 / 层 3 测试项数与基线一致。

## 决策记录（后果两面）

### D1 唯一权威放在装配层预扫描，而非渲染层

- 收益：登记时序先于任何渲染，主场不随板块序漂移；与 `getTopicMainContentTexts` 现有注释的
  「为什么必须预扫描而非渲染时登记」论证一致（`report.ts:131-137`），代码与注释从「声明一套、
  做一套」变为一致。
- 代价：`makeContext(chart, topic, {})`（预扫描）与 `makeContext(chart, topic, options)`（渲染）
  的等价前提成为隐式契约，必须由对拍断言明示守卫（本 change 交付）；若未来内容随视角变化，
  这是必须重开的决策点，不是可局部修补的实现细节。

### D2 views 两处渲染期登记保留

- 收益：surround 的登记服务「渲染时才发现的他星全文」——这些文本不在任何预扫描清单里（预扫描
  只清单本板块核心论断），删掉它三方联动就失去登记能力，后续板块遇同文会重复输出全文；mutagen
  的登记是 spec「四化注首现原则」的载体。两者各有 spec 条款、语义自洽。
- 代价：`dedupe` 表因此仍有两个写点（预扫描 + surround）加一个写点（mutagen），不是单写点表。
  接受理由：写点语义互不重叠（主场 / 他星首现 / 四化注），且「多写点」本身不是病，无主的双份
  实现才是。

### D3 对拍断言的形态：取材对比 + 表键检查 + 落点计数，而非解析渲染文本

- 收益：三个断言各钉一个失败模式——
  1. **取材对比**（预扫描 vs 非缺省 options 的 `buildOverviewMaterial`）：钉等价前提（内容 vs
     视角），文本解析做不了这件事；
  2. **表键检查**（fresh dedupe 过一遍 `getTopicReport` 后，预扫描全文不得入表）：钉「第二登记
     点回归即红灯」，这是纯输出断言做不到的（内联 set 恢复在无同文冲突时输出逐字节不变）；
  3. **落点计数**（每条预扫描全文在其主场板块出现且全报告恰一次）：钉端到端不落空，覆盖
     「预扫描漏登 / 多登」两类漂移。
- 代价：表键检查依赖一个结构事实——单板块渲染内，surround 不可能登记本板块主星全文（本宫被
  `isMain` 跳过、sanFang 各宫 contentKey 互异、四化注是另一文本域）。该事实不经证明不可见，
  必须由突变实验实证（任务 4.2：恢复内联 set → 断言红；若出现假红即设计失效，回炉重设计）。
  文本对比被否决的补充理由：版式改版会误伤断言，守的是症状不是契约。

### D4 starBadge 死 import：独立任务、独立 commit，不顺带

- 收益：主删改的基线对账 diff 清单严格限于「预期内输出差异 = 0 行」，评审逐字节可对；死 import
  清除的动机（复核发现）与主删改（评委裁决）不同源，分开可各自回滚。
- 代价：多一个 commit。接受理由：AGENTS.md「最小 diff」纪律的红线是夹带无关改动，一行 import
  的清除虽同文件，仍按纪律单列。
