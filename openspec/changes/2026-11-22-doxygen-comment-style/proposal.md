# Proposal

## Why

仓库已有较完整的 JSDoc 基础，但文件级标识不统一，也没有明确规则区分文档注释、普通解释性注释和注释掉的代码。直接全量转写容易丢掉既有约束、指针或引文，收益却主要在文件级导航和 API 悬停。用户已拍板：建立 Doxygen/JSDoc 文件级规范，保留已有有效注释，普通解释性注释渐进整理。

## What Changes

- **`code-style` spec 升级**（折回后生效）：非生成物 `.ts` 文件使用带 `@file` 的文件级文档注释，用一句话说明文件职责；规定 shebang、普通块注释、行内注释、注释掉的代码与工具指令注释不纳入本次转换。
- **保留既有有效内容**：文档正文中的约束、陷阱、示例、指针、引文及归属，以及 `@packageDocumentation`、`@throws`、`{@link}` 等已有有效标签，不因格式统一而删除。标签集是最低约定，不是封闭白名单。
- **小规模落地**：为 `scripts/` `test/` `tools/` 下尚无文件头的非生成物 `.ts` 文件补文件头；已有文件头只在缺少 `@file` 时补充标签，既有正文原样保留。
- **符号级补充**：为 `scripts/` `test/` `tools/` 下非生成物 `.ts` 的导出符号（函数、类、接口、类型、导出常量）补文档注释，共 275 个：导出函数标注 `@param` / `@returns`，其余说明「是什么」。只写可从实现或既有注释确认的事实，不编造行为与边界。
- **普通解释性注释渐进整理**：后续修改相关文件时按现行 why 优先规范处理，不为统一形态单独批量改写，也不在本次顺手删除所谓冗余注释。
- **生成物不动**：`scripts/data/wenmo-tables.ts` 与 `scripts/corpus/data/tianji.ts` 跳过。`docs/cli-samples.md` 不在本次源码范围内，只需确认零 diff。

### 不做什么

- **不引入 Doxygen 工具链**：「Doxygen 格式」指 Doxygen/JSDoc 兼容子集，不新增 Doxyfile，不调用 doxygen 二进制。
- **不全仓转写注释**：不把 `//`、普通 `/* */` 或注释掉的代码改成文档注释，不要求所有符号补齐参数、返回值或示例标签。
- **不无中生有写 API 文档**：只为**已存在的符号**补「是什么」与参数/返回说明；不为不存在的符号造文档，不写未经验证的行为、边界或性能结论。确认不了的符号保留现状并登记。
- **不动行为与既有规范语义**：排盘内核、CLI 分发、输出契约、引文与指针零变化；现行 why 优先与长注释外置规则的适用面不因本次文件级规范而改变。
- **不扩大生成物判定**：本次明确跳过上述两份 TS 生成物，不靠文件头文字猜测生成物身份。

### 被否决的备选方案

- **全仓 161 文件批量转写**：现有源码已大量使用 JSDoc，主要缺口是文件级标识；全量改写增加语义丢失和审阅成本，收益有限。
- **限定封闭标签白名单**：会误删 `@packageDocumentation`、`@throws`、`{@link}` 等已有有效信息。
- **仅依赖既有测试证明注释保真**：既有守卫能发现部分无效指针和伪造引文，不能证明原指针、引文及归属没有丢失，须另做基线对拍。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `code-style`: 新增文件级 Doxygen/JSDoc 注释规范，并明确既有内容保留与非转换范围。

## Impact

- **规范面**：`openspec/specs/code-style/spec.md`（archive 折回后）。
- **代码面**：仅缺失 `@file` 的非生成物 `.ts` 文件头，以及必要的临时校验脚本；既有文档正文、普通解释性注释、测试断言和生成物不改。
- **守卫面**：注释指针有效性、引文守卫、层 6 源码扫描必须保持绿；另以基线与工作区的代码、指针、引文及归属对拍补足保真验证。
- **验证义务申报（三档）**：按**纯重构档**申报——先固定 HEAD 基线，剥除注释后逐文件 diff=0；执行 `typecheck`、`selftest`、`npm test`、`lint` 和 Prettier 检查。内容扩展档与内核改动档不适用。
