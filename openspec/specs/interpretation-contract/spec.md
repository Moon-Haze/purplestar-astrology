# interpretation-contract Specification

## Purpose

约束交付给用户的解读文本的章节、顺序、篇幅与边界。解读由模型撰写，但形态与口径由本契约固定——
目的是让每次交付的粒度一致、依据可回溯、边界不被省略。数据取数由 chart-casting 与
knowledge-retrieval 负责，本能力只管「怎么写」。

## Requirements

### Requirement: 全盘五节固定模板

系统 SHALL 以固定章节、顺序与命名组织全盘解读：**命宫总论 · 格局定性 · 四化着力点 · 当前大限 ·
综论与建议**，前置一行基本信息与一段总评。章节标题不得改名或调序。

解读步骤 SHALL 不跳步：命宫定基调 → 格局定性 → 四化定着力点 → 大限看阶段 → 结论落到具体建议。

#### Scenario: 标准全盘解读

- **WHEN** 用户请求完整命盘解读
- **THEN** 输出按五节顺序组织，每节标题与顺序固定

#### Scenario: 破格须说打折

- **WHEN** 命宫构成格局但带破格条件
- **THEN** 明确说出打折幅度，不按完整格局论断

### Requirement: 五种输出形态与篇幅基线

系统 SHALL 按用户意图选择形态，各形态篇幅基线固定：

| 形态 | 触发 | 篇幅 |
| --- | --- | --- |
| 全盘 | 完整解读请求 | 800–1500 字 |
| 聚焦 | 单问某宫，或用了 `--focus` | 300–600 字 |
| 主题 | 单问某主题（感情/事业/财运/健康等），或用了 `--topic` | 500–900 字 |
| 流年 | 问某一年运势，或用了 `--yearly` | 按主题形态骨架 |
| 合盘 | `synastry` 请求 | 按合盘形态骨架 |

全盘报告形态（`--report` 的 Markdown 交付物）SHALL 原样转发不改写，且不适用 800–1500 字约束——
它是交付物，完整性优先。

#### Scenario: 单问一宫

- **WHEN** 用户只问财帛宫
- **THEN** 换聚焦形态，不套全盘五节模板，篇幅 300–600 字

#### Scenario: 报告交付物

- **WHEN** 使用 `--report` 产出 Markdown 报告
- **THEN** 原样转发，不改写、不压缩篇幅

### Requirement: 边界声明不得省略

系统 SHALL 在每种形态结尾附上对应的边界声明。这是硬约束，不是可选项。

| 形态 | 结尾必带 |
| --- | --- |
| 全盘 / 聚焦 / 流年 | 本解读为传统命理体系内的静态论断，不是医疗、法律或投资意见。 |
| 主题 = health | 本节谈的是传统命理对体质与易感倾向的描述，不是医学诊断；有具体症状请就医。 |
| 主题 = wealth | 本节不涉及具体投资标的与收益预测，仅为传统命理对财务模式的描述。 |
| 主题 = 其他 / 全盘含财运节 | 涉及财务处为传统命理描述，不构成投资建议。 |
| 合盘 | 星级为依传统标准的裁量结论，不是对两人关系的判定。 |

#### Scenario: health 形态

- **WHEN** 用户问健康主题
- **THEN** 只写「体质偏寒 / 脾胃为薄弱环节」这类体系内描述，附 health 边界声明，
  **不写**「你可能有某某病」，不给治疗方案

#### Scenario: 用户描述具体症状

- **WHEN** 用户在健康话题里描述了具体症状、用药或检查结果
- **THEN** 明确转向「这需要医生判断，命理不能替代」

#### Scenario: wealth 形态

- **WHEN** 用户问财运主题
- **THEN** 可写财源类型、聚散节奏、四化落财帛宫的含义，**不写**具体股票/基金/房产买卖时点
  与收益预测

#### Scenario: 合盘星级

- **WHEN** 输出合盘星级
- **THEN** 同句注明星级是依传统标准的裁量结论，不是命令输出的客观分

### Requirement: 虚岁口径不得换算

系统 SHALL 一律报 CLI 给出的虚岁，不得自行换算成周岁。换算即错，且会连带说错当前大限。

#### Scenario: 报年龄

- **WHEN** 解读中提到命主年龄
- **THEN** 用 CLI 给的虚岁原值

### Requirement: 口径提示先转达后解读

系统 SHALL 在进入解读**之前**转达完 CLI 输出里的口径提示：真太阳时校正量、跨午夜改期、
晚子时两盘对照、城市歧义候选。不得在解读里装作没有这回事。

#### Scenario: 晚子时

- **WHEN** 用户给 23:xx 出生，输出含两盘差异对照
- **THEN** 先逐字读出提醒里的紫微落宫与命宫主星两组值，说明差异有多大并建议确认钟点，
  再进入解读；不得自行替用户选口径

#### Scenario: 跨午夜改期

- **WHEN** 输出写明真太阳时已跨过午夜、日期回退或顺延
- **THEN** 以输出里的日期为准，并向用户说明这是真太阳时的结果而非排错

#### Scenario: 城市歧义

- **WHEN** 输出给出城市歧义候选
- **THEN** 转达候选并请用户确认，不静默取其一

### Requirement: 断语可回溯

系统 SHALL 保证每个断语都能指回 CLI 数据（星 / 宫 / 格局名），不凭记忆加星。
首次出现的术语配一句白话。全文表格不超过 2 张，且只用在四化节。

语气 SHALL 为直断——先给结论再补依据。

#### Scenario: 十二宫领域

- **WHEN** 聚焦/主题/四化形态需把宫名翻成「这宫管什么」
- **THEN** 用十二宫主管领域白话对照表翻译，且宫名口径一致（第 8 宫是交友宫，不是仆役宫）

#### Scenario: 不凭记忆

- **WHEN** 断语涉及某星
- **THEN** 该星来自 CLI 输出，不补充记忆中的星曜性质
